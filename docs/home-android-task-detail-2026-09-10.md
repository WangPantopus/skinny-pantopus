# Android Home task detail and capabilities — September 10, 2026

This checkpoint replaces the household task detail placeholder with a real read-only task screen and connects list/detail controls to current server capabilities. Creation recovery, edit-form session binding and private attachment controls remain the next native task slice.

## Implemented behavior

- The task collection decodes `collection_capabilities.can_create`, each task's `can_edit`, `can_complete`, `can_delete`, and the exact `task_session`. Missing permissions never enable an action. No role, owner flag, assignee inference or broad Home permission substitutes for a record capability.
- Every new task access controller captures the existing live account/session/API origin before its first suspended request. Initial and subsequent responses must match the opening actor, exact Home and fixed server session fingerprint; task detail also requires the exact task ID. TokenStorage/session replacement rejects late responses.
- A task row opens actual read-only detail. Description, status, type, due date, assignment, recurrence and visibility are displayed without requiring edit permission. Edit navigation rechecks the exact current task and `can_edit` before opening the existing form.
- Collection create affordances appear only for `can_create`; invoking an old callback rechecks current collection authority. Completion and deletion use the current exact record capability and expected session header. Completion sends only the desired status, leaving completion timestamps to the server, then fetches current projected record capabilities. Deletion requires the exact server message `Task deleted`; malformed HTTP 200 bodies remain failures.
- Synchronous in-flight guards prevent repeated taps from issuing concurrent mutations. A failed access check or unknown mutation result clears stale metadata and controls instead of reporting success or restoring a possibly revoked task. Returning from a form or the background refreshes current data. Session invalidation retires existing metadata immediately. Screen pause/disposal cancels in-flight work, clears content and invalidates its generation; late permission reads cannot navigate or publish after the screen closes. Resuming reuses the same opening identity.
