# Open review issues for 00a after 2 fix rounds (round-2 verifier findings; the round-2 fix was applied but not re-verified)

- [major] (contract) One of ProvenanceMark's own in-context crops breaks invariant 1 and the component's accessibility rule. The f5-today-calendar-strip crop (04b) draws unconfirmed and you-added marks, in the strip and in the six rows under it, but never prints a legend or a first-occurrence word. The other two crops do: (a) has a legend strip and (c) prints the word beside every mark. Every later screen copies these crops, so the calendar strip would ship without its words.
  - evidence: Contract ProvenanceMark accessibility: "each surface shows a legend or a first-occurrence word once." House style invariant 1: "Each surface shows the matching word once (a legend or first-occurrence label)." Prompt 04b only says: "a 14-cell strip ... at XS 12pt, one ink colour" plus rows such as "Recycling and garbage" / "Tomorrow" (unconfirmed), with no word or legend.
  - fix: In crop b, add the legend line ("Official · On record, not confirmed · You added this" with drawn marks) above the strip, or print the word next to the first row that uses each mark (for example "Tomorrow · On record, not confirmed"). Label it "legend once per surface".
- [minor] (contract) The prompt's default drawing is the radio indicator that conflicts with invariant 1: an empty ring for unselected AX5 rows, which is the UNCONFIRMED silhouette. The invariant is a product decision the house style says not to reopen. The prompt does flag this on Notes A7 and gives an alternative. But iOS has no native radio control (native list selection is a trailing checkmark), so a "24pt platform radio indicator" is not a real platform control on iOS.
  - evidence: B8: "its unselected form (AX5 rows only) is an empty ring." KindGlyph 03: "Unselected rows show an empty 2px ring in text.secondary." Notes A7: "the UNSELECTED option is an empty ring — the same silhouette as the UNCONFIRMED mark — and that is the sharpest conflict." House style: "Filled vs hollow means provenance and nothing else."
  - fix: On iOS AX5 rows, draw the flagged alternative by default: a trailing check on the selected row and nothing on the others. Keep ring radios only for Android M3, where they are the platform control, and keep the Notes question for the founder.

- [major] (quality) The publish-name grammar does not produce stable, unambiguous names for the 59 later prompts to reference. Grid labels contain '/' and parentheses, some rows are labelled with fixture strings, and the example names do not follow the rule 'spelled exactly as the row and column labels'.
  - evidence: The grammar is "<Component> / <variant> / <state> / ...". But the ProvenanceMark column label is "tinted/accented widget rendering (silhouette only)" (contains '/'), and the example uses "tinted widget". FreshnessLine R2 is labelled "'Updated just now' / 'Updated 12m ago' / 'Updated 2h ago'". The ChoiceChip example "ChoiceChip / time / selected / web / dark" names a platform cell the grid never draws per platform.
  - fix: Add a short printed key to every grid row and column and require the publish names to use only those keys (lowercase-hyphenated, no '/'). Examples: ProvenanceMark states default · stale · in-target · tinted-widget · greyscale. FreshnessLine variants updating · updated · failed · offline · fact-stale · widget-horizon. StatusChip variants upcoming · due-today · overdue · paid · expires · declined · waiting · deadline · deadline-today, with the fixture string shown only as the specimen text. Make the examples match these keys, and use "any" for ChoiceChip except the R5 platform forms drawn on 01-anatomy.
