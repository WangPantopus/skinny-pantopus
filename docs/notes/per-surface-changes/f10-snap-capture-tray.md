# Research-backed changes for f10-snap-capture-tray

- Redraw as a post-capture queue. The system scanner (VNDocumentCameraViewController / ML Kit SCANNER_MODE_BASE) handles capture; the tray shows returned pages with upload rings, 'Scan more' and 'Done (N)'. No custom viewfinder chrome [capture]
- Tapping a thumbnail reveals a visible action row, 'Retake · Delete · Same letter as previous', at 44pt/48dp; long-press and hover are shortcuts only. Delete before upload is instant with Undo, no dialog [capture, a11y]
- One page = one piece by default; joined pieces show a stacked thumbnail with '2 pages' [capture]
- Audience line: 'Only your household can see these photos: you and Sam', with a permission variant [capture]
- Fallback frames: scanner unsupported (iOS isSupported false, Android RAM under 1.7GB) → photo picker or a single shot; camera permission denied on iOS and web only; 'Choose from photos instead' needs no library permission [capture]
- Web: drop target plus 'Choose files'; mobile web 'Take a photo' plus 'Choose from library'; convert HEIC before thumbnails; realistic rejection examples; decide how single-page PDFs are handled [capture]
- Progress rings carry text ('2 of 3 uploaded'); works in landscape [a11y]
- (research contradiction, topic capture-and-extraction: photographing pa) v1: 'Viewfinder filling the sheet on native... on iOS it wraps the system camera picker, on Android CameraX', with a Pantopus thumbnail strip, counter, privacy line and 'Add another' drawn inside that capture view. A 'camera permission denied' frame is drawn for all platforms, Android included. | research: The platform document scanners (VNDocumentCameraViewController, ML Kit GmsDocumentScanner) provide auto-capture, edge detection, crop and multi-page batch, and their UI cannot be customised. ML Kit exposes only gallery import, page limit and mode. A system camera picker takes one shot with no edge detection, the exact one-shot shape v1 forbids. A custom CameraX viewfinder means re-implementing edge detection and perspective crop, heavy for a solo founder. ML Kit's scanner needs no camera permission but requires at least 1.7 GB RAM, and VisionKit exposes isSupported. | do: Redraw the tray as a post-capture queue. The system scanner handles shooting; the tray (over Mail Day) shows the returned pages with upload rings, delete, retake (reopens the scanner), 'Same letter as previous', the audience line, 'Scan more' and 'Done (N)'. Replace the Android permission-denied frame with a 'scanner unavailable on this device' frame that falls back to Photo Picker or a single camera shot. Keep permission-denied for iOS and web.
- (research contradiction, topic capture-and-extraction: photographing pa) v1: Each thumbnail carries 'its own small delete control and a "Retake" affordance on long-press/hover'. | research: Apple HIG: a custom gesture must be 'Not the only way to perform an important action', and buttons need at least a 44x44 pt hit region. Android recommends 48x48 dp. WCAG 2.5.8 sets a 24x24 CSS px minimum. A small delete glyph on a thumbnail that also carries a progress ring invites mis-taps on a destructive control. | do: Tapping a thumbnail selects it and reveals a visible action row (Retake · Delete · Same letter as previous) with 44 pt / 48 dp targets. Long-press and hover are shortcuts only. A deleted shot disappears with an Undo, not a dialog.
- (research contradiction, topic capture-and-extraction: photographing pa) v1: The always-visible privacy line reads 'Photos are stored privately to your home and never shown to neighbors.' | research: The real exposure of a photographed bank statement is inside the household. Zeng & Roesner found multi-user homes lack access control and have tensions even when non-adversarial. Apple HIG asks for transparency about how data is used. House honesty rule 2 requires every surface to say 'Only you' or 'your household'. The line names neither the audience nor the members. | do: 'Only your household can see these photos: you and Sam.' If finance permissions differ, say so here and on the privacy card, as in the next entry.
- (research contradiction, topic capture-and-extraction: photographing pa) v1: Rejected-file examples: 'IMG_4417.HEIC is 31.4 MB — mail snaps have to be under 25 MB' and 'statement.pdf isn't a photo — take a picture of the page instead'. The web desktop drop target reads 'Drag photos here, or choose files'. | research: Only Safari 17+ displays HEIC (caniuse), so HEIC uploads need conversion before web thumbnails render, and typical iPhone HEIC photos are rarely anywhere near 31 MB (a realism note, not a sourced figure). On desktop the capture attribute falls back to a file picker (MDN), which is where people drag e-bill PDFs. Scanner apps and ML Kit commonly produce PDFs. | do: Moderate. Keep the specific-reason pattern, but make the examples realistic: an oversized ProRAW or scan file for the size case. Either accept single-page PDFs on web (render them server-side) or change the PDF copy to a constructive fix that fits a desktop user ('PDF bills aren't supported yet — add the due date by hand instead', linking to the Date sheet). Convert HEIC to JPEG before any web thumbnail.
- (research contradiction, topic accessibility-inclusive: WCAG 2.2 AA (in) v1: Each thumbnail has 'its own small delete control and a "Retake" affordance on long-press/hover'. | research: Hover and long-press-only actions are hidden and fail gesture-alternative guidance (Apple HIG; WCAG 2.5.1 intent; 1.4.13 for hover content). Small delete controls on 56px thumbnails fall below 44pt/48dp. | do: Show Retake and Delete as visible labelled controls (for example in a selected-thumbnail action row) with 44pt/48dp targets. Expose them as custom actions on each thumbnail, and give each progress ring a text value.
