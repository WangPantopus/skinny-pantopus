# Research-backed changes for f11-keeper-naming

- Opens only from a tap, after a value moment, never auto-presented (overrides design doc §F11 'second Today open') [companion, onboarding]
- One sheet: 6 species with a pre-filled name each, a 24-character limit, no pronouns, traits or colours; a full-weight 'Skip'; visible Close [companion, a11y]
- Selection is a filled radio dot plus bold label with the selected trait, distinct from the focus ring; no automatic focus move to the name field [a11y]
- After naming: the pose settles plus one factual line; no confetti or sound. After Skip: the Today slot closes; re-entry through the place file and Settings [companion]
- Neutral remove copy ('Remove keeper'); nothing is gated behind naming; at AX sizes tiles go to one column and the sheet scrolls [companion, a11y]
- (research contradiction, topic companion-progress-ethics: companion cha) v1: State 6: after Skip, 'Today drawn with the quiet inline invitation still in the keeper slot'. The keeper-strip prompt likewise keeps an 'Unnamed' invitation in place, even though the naming prompt says Skip 'never asks again'. | research: Apple's HIG on onboarding says not to present a skipped flow again on later launches and to make it findable in settings or help. Deceptive.design classes 'Not now' without a permanent dismissal as nagging. The European Parliament's 2023 resolution calls for attention-seeking features to be off by design. | do: After Skip, the keeper slot on Today closes entirely and Today looks the way it does for a user who has no keeper. Re-entry is a row in the place file's Place section and a Settings item. Update the Skipped frame and the strip's Unnamed frame to match.
- (research contradiction, topic accessibility-inclusive: WCAG 2.2 AA (in) v1: Tile selection is a '2px border.focus ring plus a primary.50 fill', with no checkmark. The name field 'takes focus automatically once a species is picked'. | research: Using the focus colour and ring for selection makes focused and selected look the same for keyboard and switch users (WCAG 2.4.7). primary.50 against white adds almost no contrast. Moving focus when a choice is made is a change of context under WCAG 3.2.2, and it disorients screen-reader users as the keyboard covers the tiles. | do: Use a selection cue distinct from focus that isn't a completion tick (for example a filled radio dot plus a bold label, exposed as the 'selected' trait) and keep the focus ring offset. Don't move focus automatically. Place the field directly below and let the user tap it, or move focus only when no screen reader is running.
