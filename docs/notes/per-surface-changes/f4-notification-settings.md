# Research-backed changes for f4-notification-settings

- Five groups mapped 1:1 to channels: Briefings; Air & weather alerts; Dates & bills; Household activity; Account & security. The helper text under each master row states the delivery level ('Quiet — shows in your list, no sound'); only the air group says it can come through Focus [notifications, household]
- Each row reads its own OS state: 'Off in Android settings · Open' (channel deep link); an iOS Scheduled Summary caption; air alerts with Time Sensitive off. A switch never reads ON when nothing can be delivered [notifications]
- The air threshold uses three radio rows with full labels and a meaning line each, defaulting to what the server enforces (101) [a11y, competitive]
- One-time migration line: 'We moved your home reminder settings here. Nothing you turned off was turned on' [competitive]
- Evening briefing row: 'Last sent Mon 6:00 PM (pickup)' / 'Skipped tonight — nothing needed you' [notifications]
- A denied banner with 'Open Settings' is appropriate here only; the widget is offered once as the alternative [notifications, widgets]
- No keeper group, no 'Tips and news' switch, and 'Pause briefings until…' with the end date named [companion, notifications]
- Help sits in the same slot as on the other settings pages; saves are status messages [a11y]
- (research contradiction, topic notifications-permissions: push and perm) v1: The OS permission state appears only as one global 'Notifications are off for Pantopus' banner; the group switches otherwise read their saved in-app value. | research: On Android a user can block a single channel while the app keeps permission ("The user has complete control"). On iOS, alerts can be off while the app is still authorized ("Authorization does not guarantee that alerts always appear"), notifications can be held for Scheduled Summary, and Time Sensitive can be switched off. v1's own rule is that a switch must never read ON when nothing will be delivered. | do: Add frames for: an Android group blocked ('Off in Android settings · Open', using ACTION_CHANNEL_NOTIFICATION_SETTINGS); iOS Scheduled Summary ('Pickup reminders may arrive with your summary'); and air alerts with Time Sensitive off. The 'Pantopus Notification Settings' link in iOS Settings (providesAppNotificationSettings) should land on this page.
- (research contradiction, topic accessibility-inclusive: WCAG 2.2 AA (in) v1: The air-alert threshold is a three-segment control: 'Sensitive groups (101+)' / 'Unhealthy (151+)' / 'Very unhealthy (201+)'. | research: Segmented controls don't wrap. At AX sizes or 200% these labels truncate, and Apple's Larger Text criteria reject unreadable truncation. NN/g's seniors research reports trouble with compact controls on touch. | do: Use three radio rows, each with its full label and a one-line meaning, at all sizes or at least at AX sizes. Keep helper text under each master switch as specified.
- (research contradiction, topic Competitive and adjacent product teardow) v1: Per-home notification toggles are 'DELETED, not rewired' into the new page. No state shows what happened to values users had set before. The AQI threshold control defaults to 'Unhealthy (151+)'. | research: Nextdoor reviews repeatedly complain that updates change notification settings and widen scope without consent. NN/g notes users rarely customize defaults, so the migrated default becomes the setting. Apple HIG asks for honest urgency. The design doc says alert_checker fires at AQI ≥ 101, so a default of 151 would show a setting that doesn't match what the server sends, unless the backend adds a per-user threshold. | do: Add a one-time 'migrated' state: 'We moved your home reminder settings here. Nothing you turned off was turned on.' Carry every 'off' value forward. Make the threshold's default match what the server actually enforces, or mark the control as depending on backend support for per-user thresholds.
