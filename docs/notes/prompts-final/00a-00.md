# Foundations 00a-00 — board setup
id: 00a-00 · clean: False

SETUP 00a-00. Foundations board 00a: Marks, captions and chips. Draw nothing yet.

Use the Pantopus house style pasted above. This project is the Foundations board 00a.
TYPE: NEW (a component specimen board).
ATTACH: none. Nothing here has shipped. Tokens, type scale and base icons come from the published Pantopus design system.

WHAT THIS BOARD IS FOR
The first design work for Pantopus, before any screen. It draws nine components once, precisely, with every variant and state: ProvenanceMark · SourceCaption · ScopeChip · FreshnessLine · OfflineNotice · StatusChip · KindGlyph · AddressChip · ChoiceChip. Every later screen is designed in a separate project with no memory of this one and uses these exact names, so label everything with its name, keys (B12) and tokens.

HOW THIS PROJECT RUNS
- The board rules (B1–B17) and the Notes rules below apply to every artboard in this project.
- Next, I send one component message per turn, in order. Each one opens with "Component 00a-NN: <Name>." and carries that component's specification, its ARTBOARDS list and its BATCH PLAN.
- A long component arrives in parts (for example 00a-NNa, then 00a-NNb). A part message takes the place of "continue" and carries the specification for the next batch. Specifications from earlier parts of the same component still apply.
- Draw only the current batch (at most 6 artboards), in the listed order. Then stop and wait for "continue", the next part or the next component message. If a batch will not fit, finish the artboards in order and say which ones moved to the next turn.
- Everything you need is in this message and the current component message (with its earlier parts). Components already drawn here are final; reuse them exactly when embedded. Never rely on any other project, file or link.
- Where a component message differs from a board rule, it wins for that component only, and the difference goes on Notes.

PUBLISH (a founder step; you only prepare the index)
When the founder accepts a component, the founder adds it to the published Pantopus design system under its exact name, so it comes out identical on all 59 later surfaces. Make this mechanical: list every specimen name on 00a · Notes, section E. Give one name per drawn grid cell, plus one for each anatomy size or platform form the component message lists under PUBLISH KEYS. "Does not apply" cells get no name.
  <Component> / <variant> / <state> / <size|platform> / <light|dark>
<variant> and <state> are exactly the printed keys (B12), never the labels. The <size|platform> slot takes exactly one of these strings: size codes in uppercase (XS, S, M, L, OG); platform codes in lowercase (ios, android, web); otherwise "any". It is "any" unless the component message says otherwise. Example: "StatusChip / overdue / default / any / light".

======================================================================
BOARD RULES
======================================================================

B1. Artboards. Every artboard is 1440 px wide and as tall as its content needs, on surface.app (light) or dark surface.app (dark). A component message may set a wider artboard for a grid (for example 2000 or 2400 px); that message gives the margins, label column and gutters, and records the width on Notes, section A. Name each artboard "00a · <Component> · <NN-state> · <light|dark>". The component name takes the house style's platform slot, because one specimen artboard shows all three platforms. The only other artboard is "00a · Notes". Print each exact name above its frame in label 13/18/600 text.strong. The standard kinds are:
  01-anatomy: callouts, TOKEN AND CONTRAST TABLE, ACCESSIBILITY, COPY, PLATFORMS, INSTEAD OF.
  02-variants-states (light and dark): the variant × state grid.
  03-scaling-greyscale: AX5, 200% and web zoom frames, GREYSCALE and INCREASE CONTRAST.
  04-in-context: crops of real surfaces. Label each crop with its surface id, platform, width and fixture (Home A, Place B or Friend C).
The component message lists its exact artboards and any extra dark twins.

B2. Top block. Inside each component artboard, print the component name in h1 30/36/700 text.primary, its one-line purpose in body 16/24 text.secondary, then "Used in:" plus the line the message gives, in caption 12/16 text.secondary, exactly. Each section below gets an overline 11/16/600 caps heading (ANATOMY, GREYSCALE and so on).

B3. Specimen cells. Draw each specimen on a surface.base card (radius lg 12, shadow sm, 16 px padding) unless the cell names another surface. Under the card, print its cell label in caption 12/16 text.secondary: its keys, size and surface, joined by " · ". Example: "official · default · S 16pt · on surface.base".

B4. Callouts. Draw 1 px text.secondary leader lines that end in a numbered SQUARE badge (16×16, radius xs 4, surface.sunken fill, label 13/18/600 text.strong numeral). Beside each number, give the measurement and token in caption 12/16 text.strong, for example "[1] 12pt disc · ink text.secondary". Badges are square because circles are reserved (B8). Callout numbers written [1]–[7] or ①–⑦ in a component message are these square badges; never draw them as circles. Dimension lines are 1 px text.secondary with 4 px end ticks and the number centred.

B5. Units and sizes. The first time a size appears in a section, give it three ways: "16pt / 16dp / 16px" (iOS / Android / web; the values are equal). Spacing uses only 4, 8, 12, 16, 20, 24, 32, 40, 48 and 64. Type uses only the type scale, the large-text sizes in B9, and any deviation a message records on Notes. Any other dimension is allowed only where this setup or a component message states it.

B6. Tokens by name, and dark mode. Label every colour by its token name. Hex values appear only in each TOKEN AND CONTRAST TABLE; the values below are for you. Dark artboards use:
  surface.base #FFFFFF → dark surface.base #0F172A
  surface.raised #F9FAFB → dark surface.raised #1E293B
  surface.sunken #F3F4F6 → dark surface.sunken #0F172A (same as dark base)
  surface.app #F6F7F9 → dark surface.app #020617
  surface.muted #F8FAFC → dark surface.muted #111827
  text.primary #111827 → dark text.primary #E5E7EB
  text.strong #374151 → dark text.strong #F1F5F9
  text.secondary #6B7280 → dark text.secondary #94A3B8
  text.muted #9CA3AF → dark text.muted #64748B (disabled controls and placeholders only)
  border.default #E5E7EB → dark border.default #1F2937 (decoration only)
  border.strong #D1D5DB → dark border.strong #374151 (decoration only)
  border.focus #0284c7 → dark border.focus #38BDF8
  primary.700 #0369a1 (links, selected text, selected edges) → "primary.400 (dark link)" #38BDF8, the same value as dark border.focus. Use that exact name on the board.
  primary.50 #f0f9ff (selected fill) → primary.900 #0c4a6e with dark text.primary on it. primary.400 (dark link) on primary.900 is for glyphs and edges only.
  primary.500 #0ea5e9 appears only where a component message names it.
  semantic.success #059669, semantic.warning #D97706 and semantic.error #DC2626 keep their hue in dark mode and go on glyphs only. primary.700 stands in for semantic.info where a message says so.
  Sunken fills: dark surface.sunken equals dark surface.base, so a sunken fill vanishes on a dark base card. Use dark surface.sunken on dark surface.raised, and dark surface.raised on dark surface.base or dark surface.app. These fills need no border.

B7. Contrast numbers. Ratios are WCAG 2 ratios computed from the real tokens. A colour at an opacity is alpha-blended over its surface in sRGB with unrounded channels, and every ratio is rounded to 2 decimals at the end. Each component message's TOKEN AND CONTRAST TABLE gives the figures that component needs. Print them exactly as given, and do not recompute them.

B8. Circles are reserved. Only ProvenanceMark may draw a solid disc, a ring, or a disc with a knocked-out tick. This covers any glyph silhouette and any drawn dot, bullet or badge. The typographic middle dot (·) in text is allowed. Round sub-parts inside a larger glyph are fine (a head, cart wheels, a pin's hole). Draw dot groups inside a glyph as short dashes or small rounded squares. The only other exceptions are the platform radio indicators that a component message names and flags on Notes. No iOS or web frame draws an unselected radio ring; the only ring in those frames is ProvenanceMark's unconfirmed mark.

B9. Large text. AX5 frames (iOS, 393 wide): caption 40pt, label 44pt, bodySmall 46pt, body 53pt. Android 200% frames (412 wide): caption 24sp, label 26sp, bodySmall 28sp, body 32sp. Crop both frames to the component and its row. Pairs stack, text wraps and never ends in an ellipsis, pills that must wrap become rounded rectangles (radius lg 12), and hit areas grow. Glyphs and marks scale with their text, capped at 2× their default size; a component message states any size that does not scale. Web 200% zoom frames are 390 px wide, a 195 px effective viewport, so they show the narrowest layout. A message that needs the wide zoomed form asks for a 1440 frame at 200% (720 px effective).

B10. Greyscale. Each light 03 artboard repeats the light grid at 50% scale, fully desaturated, unless the message sets a different scope. Next to each cell, print "Reads without colour: yes — <cue>", or the failure and its fix where the message names one.

B11. Increase Contrast. Each light 03 artboard shows what changes, or prints "Increase Contrast: nothing changes — <why>". By default, text.secondary becomes text.strong (dark: dark text.strong). Disabled text.muted stays, because the reason caption carries the meaning. Each message states its result.

B12. Grids, keys and cell labels. Rows are the message's variants and columns are its states, in the given order. Draw every cell. Under each row and column label, print "key: <key>" in caption 12/16 text.secondary. Keys are lowercase and hyphenated, with no "/", spaces, fixture strings or dates. Labels may be longer and may quote fixtures. Each message lists its keys, and cell labels and publish names use only those keys. A cell that "does not apply" is an empty surface.base card reading "Does not apply — <reason>" in caption 12/16 text.secondary; a shared reason is printed in each cell. Never leave a cell blank or skip a row or column.

B13. Targets. The minimum hit area is 44pt on iOS, 48dp with 8dp gaps on Android, and 44px on web: "target (B13)". Draw it as a 1 px dashed text.secondary outline labelled "target 44pt / 48dp / 44px". Point a small "not a target" label at any mark or glyph inside a row.

B14. Focus vs selection. Focus is a 2 px border.focus ring (dark: dark border.focus) with a 2 px gap outside the shape. Selection is a fill plus a glyph, plus the edge or ink change the message states. Never show selection with a ring alone, or focus with a fill.

B15. Motion. Nothing animates unless a message says so. Where motion exists, draw its Reduce Motion pose and its end pose beside it. Any exemption from the house style's 300ms limit is stated in the message and recorded on Notes.

B16. Fixtures and dates. Use only the house-style FIXTURES and the strings quoted in the messages. TODAY is Mon 19 Oct 2026, 6:10 PM Pacific. Compute every relative time from it: "observed 7:00 AM" is "11 hours ago", Mon 26 Oct is "in 7 days", and Sat 10 Oct is "9 days ago". Date rows put the relative count first ("in 4 days · Fri 23 Oct"). "Tonight", "Today" and "Tomorrow" stand alone, with no date. A time today shows no weekday ("As of 7:40 AM"). Any other string goes on Notes, section B.

B17. Air readings. The AQI track belongs to AqiBand, which is not on this board. Air rows show the value line and caption only. No EPA ColorVision Assist hue appears, and no text sits on an AQI fill.

00a · NOTES (one artboard, built up across the project)
======================================================================
ProvenanceMark's last part creates 00a · Notes, and each later component's last batch updates it. On each update, redraw the whole artboard, keep every earlier entry word for word, and add the new entries under the component's subheading. Print numbered lists in body 16/24 text.primary on surface.base, in five sections:
  A. Deviations and decisions (each needs a founder yes or no).
  B. Invented strings.
  C. Omitted or merged states ("none" if every cell was drawn).
  D. Open questions (only where two readings would give materially different components).
  E. Publish index (every PUBLISH name, one per line, grouped by component).
Entry numbers start with the component number: 00 for board-wide entries, then 01 ProvenanceMark through 09 ChoiceChip (for example "01.A3"). Print these entries first, under "Board":
  00.A1 Artboard names put the component in the platform slot, because each artboard covers all three platforms.
  00.A2 Marks and glyphs at AX5 / 200% are capped at 2× their default size.
  00.A3 No dark primary.50 exists, so the dark selected fill is primary.900. The dark link colour is named "primary.400 (dark link)" (= dark border.focus).
  00.A4 Dark surface.sunken equals dark surface.base, so sunken fills on a dark base or app surface use dark surface.raised.
  00.A5 Dated rows follow DateRow's format (B16). DateRow owns the format, and later surfaces copy it from there.
  00.A6 Web 200% zoom frames are 390 px (195 px effective), so they show the narrowest layout.
  00.A7 Every grid row and column carries a key, and publish names use only keys.
  00.A8 Contrast figures use the B7 method (sRGB alpha blend, unrounded channels, rounded at the end). Each component's figures are printed in its own TOKEN AND CONTRAST TABLE.
  00.A9 No AQI track or EPA hue appears on this board.
  00.A10 The dark text.strong, text.muted, border.strong and surface.muted values come from the published design system, not the house style. Dark text.strong is intentionally brighter than dark text.primary, for Increase Contrast.
  00.A11 Artboards are 1440 px wide unless a component message sets a wider grid artboard; each such width is recorded under that component.
  00.A12 Publish-name size and platform slot casing: size codes uppercase (XS, S, M, L, OG), platform codes lowercase (ios, android, web), otherwise "any".
  00.B1 Board annotations: "Does not apply — …" reasons, "not a target", "target 44pt / 48dp / 44px", "Reads without colour: yes — …", "Increase Contrast: nothing changes — …".
