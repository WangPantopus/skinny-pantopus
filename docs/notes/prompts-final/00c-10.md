# Foundations 00c-10 — GrantLimitList
id: 00c-10 · clean: False · artboards: 6

Component 00c-10: GrantLimitList. Follow the board rules from the setup message.

PUBLISH NAME: GrantLimitList. This message is the complete GrantLimitList specification.

PURPOSE (print at the top of 01). Two scannable lists: what you get now (ticked) and what needs address verification (locked). One component serves invite, attestation and verify.

USED IN (panel): f3b-invitation-decision · f3-invite-composer · f3b-owner-attestation · f3b-verify-address-sheet · f9-verification-promise-copy · f3-members-roster.

EXTRA STAND-IN FOR THIS COMPONENT (label it "stand-in", per R11)
- ChoiceChip: pill, 32pt visual height inside a 44pt / 48dp target, label 13/18. Selected: primary.50 fill, primary.700 label and a leading check glyph (dark: D5). Unselected: a 1px text.secondary edge and a text.strong label. The focus ring is distinct from selection. At AX sizes the chips become radio rows. Platform notes: an iOS segmented control where native; M3 filter chips on Android.

STRING SET (exact; every variant draws from it)
- Grants: "Sees and edits the calendar" · "Sees bills and who paid" · "Sees who lives here".
- Limits: "Message your neighbors" · "Get a residency letter" · "Show your Residency Pass" · "Share what you pay in rent (Real Rent)" · "Earn a Block Founder rank".

ANATOMY (01-anatomy)
Draw the specimen twice: the stacked iOS form of V1 at 2x, and the two-column web-1440 form of V1 beside or below it at 1x (never shrunk; R2).
① Grant list heading "What you get now": label 13/18 text.strong. The grant list always comes first.
② Grant rows, 44pt each: a 16pt bare stroke check in success hue (a stroke, not a disc, so it cannot be mistaken for the YOU ADDED mark; dark: D7), a 12pt gap, and the verb phrase in body 16/24 text.primary.
③ Limit list heading "What needs address verification": label 13/18 text.strong.
④ Limit rows, 44pt each: a 16pt lock glyph in text.secondary, a 12pt gap, and the verb phrase in body 16/24 text.primary.
⑤ Callout: "both lists use identical type and row height".
⑥ Callout: "two columns 24pt apart on web 1440; stacked on mobile (iOS, Android, web 390)".
⑦ Callout: "one shared string set; every variant draws from it".
⑧ Web menu callout: "no custom actions; no row menu button".

ACCESSIBILITY (panel)
- Each list has a heading, exposed as a heading. Where there is no visible heading (V5, V5g), the list has an accessible name.
- The check and lock glyphs are decorative; the heading carries the meaning.
- Rows are read as list items: "What you get now, list, 3 items. Sees and edits the calendar."
- "Show 3 more" is a 44pt / 48dp / 44px button, spoken "Show 3 more" (the spoken name matches the visible label).
- Chips are spoken with their selected state: "Member, selected".

COPY RULES (panel)

- Use the string set exactly.
- Never write a bare product name.

PLATFORMS (panel): stacked on mobile (iOS, Android, web 390) and two columns on web 1440. The V5 chips follow the ChoiceChip platform notes (an iOS segmented control where native; M3 filter chips on Android).
