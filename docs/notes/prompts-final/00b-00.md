# Foundations 00b-00 — board setup

WHAT THIS BOARD IS FOR
This project draws seven components as reference specimens, not as screens: ScaleStrip, AqiBand, FourteenDayStrip, YearBand, SlotMeter, PublicPointMap and FactCount. Later screen prompts, sent from separate projects that can't see this one, ask for these components by exact name. Once published, these specimens are the only definition of each component. Draw every number, token and string exactly as the component messages give it.

HOW THIS PROJECT RUNS
- This message holds the board rules: G1–G8 and R1–R12. They apply to every artboard in this project. Later messages call them "the board rules from the setup message".
- After this message, I'll send one component message per turn, in this order: ScaleStrip, AqiBand, FourteenDayStrip, YearBand, SlotMeter, PublicPointMap, FactCount.
- ScaleStrip and AqiBand each arrive in two parts (part 1, then part 2). The two parts count as one component message. Part 2 relies on everything in part 1.
- Each component message (or part) includes its ARTBOARDS list and a BATCH PLAN. Draw only the first batch. Then stop and wait until I type "continue" or send the next part. Never start another component's artboards early.
- The last batch of every component updates 00b · Notes (R12).
- Everything you need is in the house style, this message, and the current and earlier component messages in this project. Don't open other projects.

PUBLISH (my step, after I accept a component)
When I accept a component, I add it to the Pantopus design system under its exact name. That includes its light and dark specimens and every variant and state. Your job is to make that step mechanical:
- Give every drawn grid cell and every named extra specimen a publish name (R10).
- List the names on 00b · Notes.
- Stand-ins (R11) and anything marked "do not publish" never get a publish name.

SHARED GRAMMAR (all seven instruments)
G1. Each instrument states its fact in words and numbers. The graphic repeats the fact and never replaces it.
G2. Nothing adds up to a grade, score, percentage or verdict. No progress ring, completion ring, countdown, streak or confetti appears anywhere. An authority's own band names are allowed even when they contain a percentage; each component message lists the allowed ones. "N of M" appears only where a component message allows it.
G3. Nothing depends on colour alone. The EPA AQI hues are the only sanctioned colour scale, and even there the category is printed in words.
G4. Three shapes mean provenance (00a · ProvenanceMark) and nothing else: a solid disc (Official), a ring (On record, not confirmed) and a solid disc with a knocked-out tick (You added this). No position marker, pointer, bullet, callout end, segment or badge on this board is a plain disc or ring. A component message that needs an exception describes it.
G5. A mark, cell or segment is never a tap target on its own. The target is the row, the whole instrument or a labelled button.
G6. Each instrument has a one-sentence summary and a spoken label, and both are printed on its artboards. The same facts also appear nearby as rows or a list.
G7. Every provenance mark keeps at least 3:1 contrast in every state. Staleness is always stated in words.
G8. Widgets and the share card are standalone surfaces. They print the provenance word next to each mark or in a legend line inside the block.

BOARD RULES
R1 · Artboard format and naming.
- Name every artboard "00b · <Component> · <NN-name> · <light|dark>", exactly as the component's ARTBOARDS list gives it. This overrides the house-style artboard pattern, because one specimen artboard shows several platforms. The last artboard is "00b · Notes".
- Each artboard is 1440 wide and as tall as its content. Light artboards use surface.app; dark artboards use dark surface.app.
- Above each artboard, print its exact name in label 13/18/600 text.strong.
- At the top inside each artboard, print three lines, as the component message gives them:
  - the component name, in h1 30/36/700 text.primary
  - its purpose line, in body 16/24 text.secondary
  - "Used in: <surface ids>", in caption 12/16 text.secondary
- Section headings use overline 11/16/600 caps, for example ANATOMY, VARIANT × STATE, AX5 AND 200%, GREYSCALE, IN CONTEXT, ACCESSIBILITY and INSTEAD OF.

R2 · Frames and cards.
- Draw specimens at true size (1pt = 1px on the artboard) inside plain frames, named as the message names them: iOS 393, Android 412, web-390, web-1440, and the widget outlines 338×158 and 338×354.
- In the three phone frames, draw the specimen card 358 wide with 16pt padding, which leaves 326pt of content width. Left-align the card at a 16pt frame margin. The right margin is then 19pt in iOS 393, 16pt in web-390 and 38pt in Android 412.
- All phone geometry assumes 326pt of content width unless a message says otherwise.
- Light cards use surface.base, radius lg 12, shadow sm and 16pt padding.
- Dark cards use dark surface.raised with a 1px dark border.strong decorative edge. The card edge carries no meaning, so the 3:1 minimum doesn't apply to it.
- Each component message gives its own web-1440 card width.

R3 · Units.
- A size given in pt is the same number in dp (Android) and px (web).
- Only target minimums differ by platform: 44pt on iOS, 48dp with 8dp gaps on Android, and 44px on web.
- Spacing uses the 4px scale: 4, 8, 12, 16, 20, 24, 32, 40, 48, 64.
- A few micro offsets inside instruments are deliberately off that scale: 6, 3, 2 and 1pt. Use them only where a component message states them, and never for layout spacing.
- Type uses only these sizes:
  - the house type scale
  - medium (500) weights of body, bodySmall and caption at the same sizes: bodyMedium, bodySmallMedium and captionMedium
  - the R7 sizes
  - the 11pt widget minimum
  - OG sizes, where a component message states them

R4 · Callouts.
- Callouts sit in an annotation gutter outside the UI, in caption 12/16 text.strong. Gutter labels ("specimen", "specimen value", "stand-in — …") use the same style.
- Leader lines are 1px text.secondary and end in a short perpendicular tick, never a dot (G4).
- Dimension lines are 1px text.secondary with 4pt end ticks.
- Each callout names the part, its size and its token, for example "Track · 12pt · fill surface.raised · keyline 1px text.secondary".
- Callouts appear on 01-anatomy artboards and wherever a message asks for them.

R5 · Tokens and dark mode.
- Label every colour by its token name. Hex values appear on the board only in contrast tables a message asks for and in the AQI swatch row.
- The dark hex values in these rules and in the component messages are for drawing. In callouts, print the token name followed by "(dark)", for example "surface.raised (dark)".
- On dark artboards, use exactly this mapping:
  - surfaces: surface.base → #0F172A · surface.raised → #1E293B · surface.app → #020617 · surface.sunken → #0F172A · surface.muted → #111827
  - text: text.primary → #E5E7EB · text.secondary → #94A3B8 · text.strong → #F1F5F9
  - borders: border.default → #1F2937 and border.strong → #374151 (both are decoration only) · border.focus → #38BDF8
  - primary.700 → #38BDF8. This applies to links, text buttons and any edge a message names, because primary.700 is only 2.47:1 on dark raised.
- These tokens keep their light values in dark mode and are labelled by token name:
  - the primary.600 fill (3.57:1 on dark raised)
  - semantic.error glyphs (3.03:1)
  - semantic.warning glyphs (4.59:1)
- Semantic hues go on glyphs only.
- On dark cards, surface.sunken fills (#0F172A on #1E293B) look darker than the card. This is intended, because keylines and text carry the edges.
- A sunken-filled shape that sits directly on dark base uses dark surface.raised instead, so that it stays visible.
- Never use the light infoBg wash in dark mode, because dark text.primary on it is only 1.16:1. Component messages give the dark highlight.
- The EPA AQI hues never change in dark mode.
- This board draws no selection state.

R6 · Contrast numbers (WCAG 2). Opacities are alpha-blended over their surface first. Use these numbers and don't recompute them. Print only the rows a message asks for. A "tinted cell" is surface.sunken at 40% over base.
Light:
- text.secondary: 4.83 on base · 4.63 on raised · 4.51 on app · 4.39 on sunken. That is below 4.5, so text on sunken uses text.strong.
- text.strong: 9.37 on sunken · 10.31 on base
- text.primary: 17.74 on base · 16.12 on sunken
- primary.700: 5.93 on base · 5.68 on raised · 5.39 on sunken
- primary.600 fill: 4.10 on base
- glyphs: semantic.error 4.83 on base · semantic.warning 3.19 on base
- stale mark (the 00a stale variant, text.primary at 50%): 3.39 on base · 3.36 on raised · 3.34 on app · 3.32 on sunken
- on a tinted cell: text.secondary 4.65 · stale mark 3.36
- Never use text.secondary at 50% or text.muted for readable text. Both fail 4.5:1.
Dark:
- text.secondary: 6.96 on dark base · 5.71 on dark raised
- text.primary: 11.82 on dark raised · 14.42 on dark base
- text.strong: 16.30 on dark base · 13.35 on dark raised
- #38BDF8: 6.83 on dark raised · 8.33 on dark base
- stale mark (dark text.primary at 50%): 4.45 on dark base · 4.10 on dark raised · 4.48 on dark app
- on a dark tinted cell: text.secondary 6.23 · stale mark 4.27
- decoration only: dark border.strong 1.42 on dark raised · dark border.default 1.00 on dark raised

R7 · AX5 and 200%.
- iOS AX5 sizes: h1 58 · h2 56 · h3 55 · body and bodyMedium 53 · bodySmall and bodySmallMedium 49 · label 44 · caption and captionMedium 43 · overline 40.
- Android 200% sizes (Android 14 non-linear scaling): h1 38 · h2 36 · h3 34 · body 28 · bodySmall 26 · label 25 · caption 24 · overline 22. Medium weights use the same sizes as their base styles.
- Web: 200% browser zoom on web-1440, which gives an effective layout 720 CSS px wide.
- Graphic geometry keeps its size, and text reflows around it. This covers tracks, cells, segments, markers, glyph-only buttons, and marks inside cells, lanes and tracks.
- Marks inside text lines (captions, rows, legends) scale with their text.
- Text wraps and never truncates or ends in an ellipsis. Side-by-side pairs stack. Widgets fall back to text only, as each message states.
- Draw iOS AX5 in a 393 frame and Android 200% in a 412 frame, each as tall as needed.

R8 · Greyscale.
- Redraw the listed specimens at 100% desaturation.
- Under each one, print in caption text.secondary the non-colour cue that still carries the meaning, in the words the component message gives.

R9 · Grids and keys.
- A variant × state grid has variant rows and state columns, in the order the message gives.
- Print each row and column label in label 13/18/600 text.strong. Under each label, print its key as "key: <key>" in caption 12/16 text.secondary.
- A key is lowercase and hyphenated. It never contains spaces, "/", a fixture string or a date. Each component message lists its keys; use them exactly.
- Each cell holds one specimen at true size, or the stacked specimens the message asks for. Under the specimen, print the cell's keys, for example "detail · stale".
- A combination that has no meaning prints "n/a — <reason>" in caption text.secondary and nothing else. Use the one reason the message gives. Never leave a cell blank.
- Every specimen outside a grid gets the extra key the message gives. So does a specimen stacked inside a cell that the message gives its own extra key.

R10 · Publish names. Give one name to each drawn grid cell and each extra specimen, in one of two forms:
- "<Component> / <variant key> / <state key> / <light|dark>"
- "<Component> / extra / <extra key> / <light|dark>"
Names use keys only. n/a cells get no name.

R11 · Borrowed parts and stand-ins.
- These instruments use parts from boards 00a, 00c and 00d. Use the published part when the design system has it.
- Otherwise, draw the stand-in described below and label it in the gutter "stand-in — the 00a/00c/00d specimen replaces it".
- Don't develop a stand-in beyond this description, and never give it a publish name.
The stand-ins:
- 00a · ProvenanceMark: a mark at XS 12pt or S 16pt, in text.secondary at full opacity.
  - Official: a solid disc.
  - On record, not confirmed: a ring with a stroke of at least 1.5px.
  - You added this: a solid disc with a knocked-out tick (a true cut-out).
  - Stale variant: the same shape in text.primary at 50%, always paired with age words.
- 00a · SourceCaption: one caption 12/16 line in text.secondary (text.strong on sunken), in the pattern [ProvenanceMark S] authority · scope word · as-of. It wraps and never truncates.
- 00a · FreshnessLine: one caption line in text.secondary that states the age in words, with an optional 16pt leading glyph.
- 00a · ScopeChip: a 24pt pill on surface.sunken, holding a 12pt person or house glyph and the label in label 13/18 text.strong.
- 00a · KindGlyph: a 24pt line icon with a 2pt stroke, in text.strong.
- 00c · InlineErrorRow: a row in the component's own slot, with no tinted background. It holds:
  - a 16pt error glyph (semantic.error on the glyph only)
  - the sentence, in body text.primary
  - a 44pt "Retry" text button in primary.700
- 00c · DateRow: a row at least 56pt tall. It holds:
  - a leading KindGlyph
  - the title, in body text.primary
  - a trailing ProvenanceMark S
  - line 2, in caption text.secondary, with the relative and absolute date ("Tomorrow", or "in 4 days · Fri 23 Oct") and a short SourceCaption
- 00c · FactRow: a 56pt row. It holds the label in bodySmall text.secondary above the value in body text.primary, a ProvenanceMark and a trailing chevron.
- 00c · TextActionRow (outbound): a row at least 44pt tall with a 1px text.secondary edge, a verb-led label in primary.700 and a trailing "↗".
- 00d · WarmingSkeleton: surface.sunken shapes with the component's final geometry and radius, and no text.
  - It reserves the exact final height.
  - It shimmers by default and is static under Reduce Motion.
- 00d · QuietDayReceipt: draw only the form a component message describes, exactly as described.
