# Foundations 00d-00 — board setup

Foundations board 00d: States, feedback and asks. BOARD SETUP.

Use the Pantopus house style pasted above. This project is one Foundations board. This message sets the board rules and draws nothing. Eight component prompts follow, one per turn: 1 QuietDayReceipt, 2 WarmingSkeleton, 3 InlineUndo, 4 DestructiveConfirm, 5 LandingBannerSlot, 6 NotificationAsk, 7 PushCopy, 8 ReminderLeadControl. Each opens with "Component 00d-NN: <Name>. Follow the board rules from the setup message." and carries that component's complete specification.

WHAT THIS BOARD IS FOR
A NEW component specimen board with no screens. These components cover the moments when the product must be honest about time and consent: nothing is wrong, something is loading, something can or can't be taken back, something is waiting, and the product wants to interrupt now or on dates you chose. Each has a quiet default; none nags. Later, 59 surfaces are designed in separate projects with no memory of this one, using these components by exact name from the published Pantopus design system. So every size, token, string and state in a component prompt is literal: draw each component once, precisely, with every variant and state listed.

HOW THIS PROJECT RUNS
1. Each component prompt has an ARTBOARDS list and a BATCH PLAN of at most 6 artboards per turn. Draw batch 1 and stop; the founder types "continue" before each later batch. After a component's last batch, wait for the next component prompt.
2. Before every batch, re-read R1–R19 and the whole current component prompt. Don't carry details between components unless a prompt says so.
3. Component order replaces the house-style priority order: finish each component, dark twin included, before the next. A named attachment arrives with its component prompt.
4. Ask a question only if two readings would give materially different specimens. Otherwise decide, and record it on Notes (R19).

PUBLISH (a founder step)
The founder adds each accepted component to the Pantopus design system under its exact name, with each specimen under the name printed beneath it (R7). Notes F lists every name.
- Every drawn specimen except the review aids below is published in light. Every specimen on a dark artboard is published in dark; every variant × state cell has a dark twin there.
- Light-only frames (platform strips, large-text frames, web-1440 crops, anything a prompt marks light only) are published in light only and listed on Notes E. A later dark surface takes their geometry from the light frame and their colours from R9.
- Review aids, never published: greyscale copies, "Not applicable" cells, "Not this" thumbnails, IN CONTEXT crops, and anything a prompt calls a review aid.

BOARD RULES

R1. Artboard names. "00d · <Component> · <NN-what> · <light|dark>", exactly as the ARTBOARDS list gives it. This replaces the house-style name format on this board, because one artboard can hold several platforms; the platform goes in each specimen name (R7). The Notes artboard is "00d · Notes", with no suffix. Print the name above the frame in label 13/18/600 text.strong.

R2. Artboard format. 1600px wide, as tall as needed, on surface.app (dark: dark app). Top left: the component name in h2 24/32/600 text.primary, then the artboard's subject in body text.secondary. Each 01 artboard also prints PURPOSE (body text.secondary) and "Used in:" (caption 12/16 text.secondary). Section headings are overline 11/16/600 caps text.strong.

R3. Platforms. Specimens are 1x at real width: iOS 393pt, Android 412dp, web-390 390px, web-1440 1440px (cropped to the relevant column, labelled "web-1440 crop"). Content width inside 16 margins: 361pt iOS, 380dp Android, 358px web-390.

R4. Units and type. pt, dp and px have equal values, except targets (R11). Spacing uses only the 4px scale. Type uses only the house-style scale, plus bodyMedium 16/24/500, bodySmallMedium 14/20/500 and the R17 large-text sizes. Other dimensions appear only where a prompt states them.

R5. Callouts. A numbered SQUARE marker (20×20, radius xs 4, surface.sunken fill, 1px text.strong outline, numeral in label 13/18/600 text.strong, centred), joined to its part by a 1px text.secondary leader. The key sits beside the specimen in caption 12/16 text.strong as number · size · token ("1 · 16pt tick glyph · text.secondary"). Markers are never circles (circles mean provenance). Dimension rulers are 1px text.secondary with 4px end ticks and the number in caption text.secondary.

R6. Grids. A "variants-by-states" artboard is a table: rows are variants, columns are states, in the order given. Headers are label 13/18/600 text.strong in sentence case ("V1 · Removed row"). Each cell holds one specimen unless the prompt lists more. Draw every cell. A combination that doesn't apply is a surface.sunken cell with "Not applicable: <the prompt's reason>" in caption text.strong, never blank.

R7. Keys and names. Each grid row and column prints "key: <key>" under its label in caption 12/16 text.secondary: lowercase, hyphenated, no "/", never a fixture string, name, amount or date. Use each prompt's keys exactly. Under every specimen, print its published name in caption 12/16 text.strong:
  <Component> / <variant-key> / <state-key> / <platform> / <light|dark>
for example "InlineUndo / removed-row / pending-undo / ios / light". Platform keys: ios, android, web-390, web-1440; large text: ios-ax5, ios-ax2, ios-ax-widget, android-200, android-150; "any" where a prompt calls a specimen platform-neutral. An anatomy specimen that repeats a grid cell carries that cell's name.

R8. Tokens. Label every colour by token name; hex appears only in R9 and R10. The house-style TOKEN USAGE rules apply: semantic hues on glyphs and borders only; text.muted for disabled labels only; readable secondary text is text.secondary on base, raised or app, and text.strong on sunken; borders are decoration, never the only edge of a control, segment or card.

R9. Dark mapping. Each dark artboard redraws its light twin:
  surface.base → #0F172A (dark base) · surface.raised → #1E293B (dark raised) · surface.app → #020617 (dark app) · surface.sunken → dark base (same colour, separates nothing)
  text.primary → #E5E7EB · text.strong → #F1F5F9 · text.secondary → #94A3B8 · text.muted → #64748B · text.inverse → #111827
  border.default → #1F2937 · border.strong → #374151 · border.focus and primary.700 → #38BDF8 · primary.50 (selected fill) → primary.900 #0c4a6e with #E5E7EB text
  semantic.error #DC2626 and semantic.warning #D97706 keep their hue.
  A dark card's edge is the fill step (raised on app), never a border, with no shadow. Dialogs and sheets are dark base. Print the container surface each prompt names in the dark frame's subject line.

R11. Targets. Minimum hit areas: 44×44pt iOS, 48×48dp Android with 8dp gaps, 44×44px web, each drawn as a dashed 1px text.secondary rectangle labelled with its size. A glyph is never a target on its own.

R12. Focus and selection. Focus: a 2px border.focus ring with a 2px gap. Selection: primary.50 fill, 1.5px primary.700 border, 16pt primary.700 check, 600-weight text.primary label (dark per R9). They never look alike. A prompt may define one further treatment, in full.

R13. Glyphs and circles. Pantopus icon set only, 16pt unless stated, 1.5px stroke. Filled vs hollow circles mean provenance only, so no glyph, tick, bullet, marker or control is a plain disc or ring; the one exception is an avatar circle (MemberRow or its skeleton), which is never a mark. A tick is a bare check stroke. No control uses a radio circle, on any platform or text size: at large sizes, the brief's "radio rows" are list rows with the R12 selection check.

R14. Strings. Use the house-style FIXTURES exactly (TODAY is Mon 19 Oct 2026, 6:10 PM Pacific). Every string comes from the house style or the current prompt; any string you add goes on Notes D. Print character counts where given. No string ends in an ellipsis unless a prompt says so. Dates show the weekday.

R15. Other boards' components. FourteenDayStrip, YearBand, KindGlyph, AqiBand, ScaleStrip, PickupCard, MemberRow and the Pantopus app icon come from the published design system. If one isn't published yet, draw a surface.sunken box at this size with its name in caption text.strong, and list it on Notes C: FourteenDayStrip 361×40pt · YearBand 361×120pt, four 24pt lanes · AqiBand 361×48pt · ScaleStrip row 361×48pt · PickupCard 361×196pt · MemberRow 361×56pt · KindGlyph 16pt or 42pt square, as stated · app icon 20pt square. Never draw a fallback where the published component exists.

R16. Disabled controls. A disabled control stays focusable and reads "<label>, unavailable, <reason>". Its label is text.muted, and the reason is also written nearby in readable text. No button is silently dead.

IN CONTEXT: two or three crops (393pt or 390px wide, about 300pt tall), each labelled with its surface id and captioned "host illustrative, not a spec", then "Also consumed by: <ids>"; draw undesigned hosts only as far as needed.
