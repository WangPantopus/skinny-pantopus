WHAT THIS BOARD IS FOR
This is a component specimen board with no screens. I will send one component per message, in this order: DateRow, FactRow, FirstWeekRow, BillRow, MemberRow, InviteRow, NotificationRow, TextActionRow, LockedActionRow, GrantLimitList, InlineErrorRow, ThumbnailRail. Each component message is that component's complete specification. This message holds only the rules for all twelve, R1 to R14 ("the board rules").
Later screen projects will use these components by exact name and key, with no other reference, so every specimen must be complete, exact and labelled. ATTACH: none.

PUBLISH
When I accept a component, I add it to the published Pantopus design system under its exact name above. Its variants and states are published under the printed keys from its grid (R7), e.g. DateRow variant "deadline-voter", state "highlighted-arrival". Never publish a drawing labelled "stand-in" (R11); those components come from their own Foundations boards.

HOW EACH COMPONENT TURN WORKS
- Each component message ends with ARTBOARDS, a BATCH PLAN and DONE WHEN. Draw only what the BATCH PLAN lists for the current turn, then stop and wait for "continue". Never start a component before its message arrives.
- Before stopping, check the batch against DONE WHEN and name anything missing.
- If a component message and these rules disagree, the component message wins; note it on Notes.
- Ask a question only if two readings would produce materially different components.

- Name each artboard "00c · <ComponentName> · <NN-what> · <light|dark>", exactly as the component's ARTBOARDS list gives it (this replaces the house style's surface naming). Show the name as a visible label above the frame in caption 12/16 text.secondary.

R2. CANVAS AND UNITS
- Artboards are at least 1440 wide, on surface.app (dark: dark app). Grow them to fit cells at 1x; never scale a cell down.
- 1pt = 1dp = 1px. Callouts give iOS pt, or all three where they differ ("44pt / 48dp / 44px").
- Row frames unless a cell says otherwise: iOS 393pt with 16pt side margins (361pt content); Android 412dp (380dp content); web-390 390px (358px content); web-1440 a 720px list column.
- Spacing and radii by name (spacing.2 = 8, spacing.3 = 12, spacing.4 = 16; md 8, lg 12).

R3. CALLOUTS
- Outside the component: a numbered circle (1px text.secondary outline), a 1px text.secondary leader, and a caption with size and token, e.g. "② title · body 16/24/400 · text.primary". Numbers match the component's ANATOMY list.
- Callouts never overlap the component. Spacing uses 1px dimension lines ("16pt · spacing.4").
- Draw every target as a dashed 1px text.secondary rectangle labelled "target 44pt / 48dp / 44px".
- Every 01-anatomy has a "web menu" callout (R12), worded as the component message says.

R4. TYPE AND LIGHT TOKENS
- Type scale only: body 16/24/400 · bodyMedium 16/24/500 · bodySmall 14/20/400 · bodySmallMedium 14/20/500 · label 13/18/600 · caption 12/16/400 · captionMedium 12/16/500 · overline 11/16/600 caps +0.5. SF Pro on iOS, Roboto on Android, system-ui on web. Amounts use tabular figures.
- Token names only, never hex on a component. Light values are in the house style; this board also uses primary.50, primary.700, errorBg, infoBg and identity.home.
- text.muted appears nowhere on this board.
- Secondary-role text (captions, "Not set", disabled labels, reason captions) is text.secondary on base, raised and app, and text.strong on surface.sunken and errorBg, where text.secondary fails (R6).
- Text buttons and links are bodySmallMedium primary.700 unless a component says otherwise.
- Semantic hues and identity.home go on glyphs and rules only, never on text.
- Border tokens are decoration. Row separators are 1px border.default hairlines inset 16pt from the leading edge, and no row relies on a hairline as its only edge. Any edge that carries meaning uses text.secondary ink.

R5. DARK MODE (every 05)
Dark tokens: surface.base #0F172A, raised #1E293B, sunken #0F172A (same as base), app #020617; text.primary #E5E7EB, text.strong #F1F5F9, text.secondary #94A3B8; border.default #1F2937, strong #374151, subtle #1E293B, focus #38BDF8. Links and text buttons use dark border.focus.
Dark has no infoBg, errorBg, primary.50, primary.700 or semantic tokens, and dark sunken equals base. Use exactly these substitutes, and record each use on Notes:
- D1 Highlight: dark raised wash plus the 4pt leading bar in dark border.focus. On a row already on raised (D3), the bar alone.
- D2 Write-failure fill: dark raised plus a 1.5px error border.
- D3 A row on sunken in light sits on dark raised, with dark text.strong.
- D4 Any sunken fill (skeleton bars, avatars, chip fills, thumbnail slots, a disabled filled button) becomes dark raised on a base row and dark border.strong on a raised row; text inside is dark text.strong.
- D5 Selection: dark raised plus a 1.5px dark border.focus edge plus a leading check in dark border.focus. Never primary.50.
- D6 Non-link primary.700 graphics (progress rings, spinners, unread dot) use dark border.focus; ring tracks use dark border.strong.
- D7 Semantic glyph hues and the identity.home rule keep their light values, on glyphs and rules only. Caption the R6 ratio beside the first occurrence on each 05.
- D8 Any card gets a 1px dark text.secondary keyline, because dark border.default on raised is 1.00:1. Caption its ratio beside the first occurrence.
Increase Contrast: no separate artboard. Every R6 check must also hold under Increase Contrast; the only change is that light cards get the same text.secondary keyline as D8. Write this once as a caption on each 05.

R7. GRID LABELS AND KEYS
- Variants are rows, labelled at the left in label 13/18 text.strong. States are columns, labelled at the top in overline 11/16/600.
- Each label reads exactly "<code> · <key>" with the codes and keys from the component message (e.g. "V3a · deadline-voter", "S2a · highlighted-arrival"). Under it, print "key: <key>" in caption 12/16 text.secondary.
- Keys are lowercase and hyphenated, with no spaces, no "/", no fixture string and no date. Publish names use keys only.
- Under every cell, in caption 12/16 text.secondary, print exactly "<ComponentName> · <variant key> · <state key>" (e.g. "DateRow · deadline-voter · done").
- Draw only the cells in GRID CELLS. Every other position stays empty canvas: no frame, no label, no "n/a".
- An n/a cell appears only where a component writes "n/a": a plain cell reading "n/a — <reason>" in caption text.secondary, with the normal cell caption. Never draw a ghost component there.

R8. TARGETS, FOCUS, HIGHLIGHT, SELECTION, DISABLED
- Targets: 44pt iOS, 48dp Android with 8dp gaps, 44px web. A ProvenanceMark, glyph or dot is never a target by itself.
- Focus: a 2px border.focus ring 2px outside the whole row. When a row holds a separate target (link, overflow, Retry, Resend, Add, dismiss), focus on it rings that target only.
- Highlight (arrival from a notification): an infoBg wash across the row plus a 4pt border.focus bar on the leading edge, full height. No outline, never a check. If the row has a 2px identity.home rule, the bar sits directly inside it. In an "on arrival" frame the focus ring is also drawn 2px outside the row, so bar and ring never touch. Dark: D1.
- Selection: primary.50 fill plus a leading check glyph. Dark: D5.
- Focus, highlight and selection must look different. Wherever a grid has a highlighted or selected cell, a focused cell sits directly beside it.
- Disabled text actions look the same everywhere: label in text.secondary (text.strong on sunken, per R4), never primary.700 or text.muted, still focusable, with a reason caption directly under it in caption 12/16 (same colour rule). Disabled filled buttons: surface.sunken fill, text.strong label (dark: D4).
- Disabled controls stay in the accessibility tree with their reason as a hint.

R9. AX5 / 200% (every 03)
- Text wraps and never truncates, except a field the component names as truncating at default sizes only.
- Side-by-side pairs stack. Trailing elements (amount, mark, chevron, text action) move below the text block, aligned to its leading edge, and keep their targets.
- Leading glyphs and marks scale with the text; ProvenanceMark keeps its shape. Row heights grow; stated heights are minimums.

R10. GREYSCALE (every 03)
Draw the whole 02 grid desaturated, same labels and captions. Beside it, caption each variant or state with its non-colour cue, e.g. "done = tick glyph + 'You marked this done'". A cell that reads only through colour is a defect: fix the component.

R11. SHARED STAND-INS
If the published design system has one of these, use it; otherwise draw this stand-in, labelled "stand-in". Components may add their own.
- ProvenanceMark: OFFICIAL = solid disc; ON RECORD, NOT CONFIRMED = ring, stroke at least 1.5px; YOU ADDED = solid disc with a knocked-out tick (a cut-out, never a second colour). Ink text.secondary (dark: dark text.secondary). S = 16pt in rows; XS = 12pt minimum. Spoken "official", "on record, not confirmed", "you added this". Filled vs hollow means provenance only. Every other check on this board is a bare stroke, never a disc.
- Legend line: "● Official · ○ On record, not confirmed · ✓ You added this" in caption text.secondary, or the word beside the first mark.
- ScopeChip: pill, 24pt, surface.sunken fill (dark: D4), 12pt glyph plus label 13/18 text.strong. Exactly "Saved place · Only you" (person glyph) or "Your household" (house glyph), spoken "Visible to only you" / "Visible to your household". Sentences exactly "Only you will see this." / "Everyone in this household will see this."; where finance access differs, name the people ("You and Sam can see these"), never "Everyone". When the chip opens the scope control, draw its 44pt / 48dp target.
- StatusChip: pill, 24pt, captionMedium, surface.sunken fill (dark: D4), text.strong; any semantic hue on a leading glyph only; one per row.
- InlineUndo: the row collapses in place to "<what happened> · Undo", announced with role=status. Undo is focusable, 44pt, and stays until the user leaves the screen. No countdown.
- WarmingSkeleton: surface.sunken bars (dark: D4) in the final geometry and height, no text, announced once as "Loading" (aria-busy on web); static under Reduce Motion.
- FreshnessLine / OfflineNotice: caption text.secondary, e.g. "You're offline · as of 5:52 PM" (invented). No banner colour.

R12. PLATFORMS AND THE WEB MENU
- Unless a component's PLATFORMS says otherwise, write "No platform differences" in its panel.
- Custom actions are VoiceOver custom actions on iOS and TalkBack custom actions on Android.
- On web, custom actions that are not already visible buttons get a row menu button: a 20px ellipsis in a 44px target at the row's trailing edge. An existing overflow button or visible buttons already are the web menu; never add a second. Draw it in every web crop where it applies.

R13. IN-CONTEXT CROPS (every 04)
- Label each crop "<surface id> · <ios|android|web-390|web-1440>". Show only enough host to place the component: outlines, section titles, neighbouring rows.
- Every crop that shows a ProvenanceMark also shows the legend line and the place's ScopeChip: "Your household" for Home A, "Saved place · Only you" for Place B.

R14. FIXTURES, MOTION, NOTES
- Use the house-style FIXTURES. TODAY is Mon 19 Oct 2026, 6:10 PM Pacific; relative counts come from it. Dates always show the weekday ("Fri 23 Oct"), never numeric formats, never "midnight". Emails use @example.com. No percentage or completion fraction is drawn on any specimen, callout or crop; an INSTEAD OF panel may name one only as the pattern to avoid.
- Motion: highlights fade within 300ms. Under Reduce Motion they cross-fade, spinners are removed and in-progress labels stay as static text. Idle loops stop within 5s.
- "00c · Notes" is the last artboard. Create it when a BATCH PLAN first says so; update it whenever a BATCH PLAN says so. One line per item.
  Board section first: each D1–D8 with the components that used it and the D7/D8 ratios; the Increase Contrast note; the R11 stand-ins you drew; any string you added that no message lists; any state you could not draw, and why.
  Then one section per component, in delivery order, under its exact name, with the lists its message gives: Invented strings · Fixture deltas · Contract conflicts (each "drawn as X instead of contract Y") · Assumptions.
