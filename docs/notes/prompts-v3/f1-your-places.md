TYPE: EXTENSION of the existing designed screen "Saved places". This screen already exists in the Pantopus design system. The attached screenshot is exact. Keep everything and change only what is listed.

PLATFORMS & VIEWPORTS: iOS 393x852 · Android 412x915 · web 1440x900 with the left sidebar, Place selected · web 390x844 with the four-tab bar, Place selected. On every web frame, draw the list inside the normal Place shell at /app/place/saved.

WHERE IT LIVES & HOW PEOPLE ARRIVE: Place tab. Entry points: (1) the Place tab itself for anyone with no claimed home: this list is the tab's first screen; (2) tapping the "Saved place · Only you" chip in Today's location row; (3) the place file's Address row; (4) "See your places" on the save confirmation; (5) on iOS, the existing saved-places route from the feed context bar; (6) Today's one-time notice after a claim (owned by the Today tab), which opens this list with the arrival line described below; (7) proposed: the Notifications settings caption that names the place briefings follow; (8) the Add a place sheet, when opened from here, returns here after saving. When the person arrives from the Today chip, scroll the row Today uses into view once, fade its highlight, and move accessibility focus to that row. Where actions lead: Open goes to that place's place file. Claim this address opens the existing claim flow, which ends on the claim receipt. + Add a place opens the Add a place sheet. After Remove, Today never shows that address again, even if Today is already open: a removed address still showing on Today reads as a privacy failure on an "Only you" surface.

The one primary action is "+ Add a place" at the foot of the list. Row actions live in each row's menu.

When the service cannot say which place Today uses, draw no badge and show an InlineErrorRow in the sentence slot.

INTERACTION, MOTION & HAPTICS: Tapping a row opens it. Tapping the menu button (44pt / 48dp / 44px) opens the menu. Use for Today: the menu closes, the badge stays where it is until the save succeeds, and the sentence slot shows "Switching Today to Mom's house…" only if the save takes 1s or longer; on success the badge and row move; on failure the InlineErrorRow appears. Remove collapses the row in place to an InlineUndo (height change 300ms or less), and the badge cross-fades to the next row in the same frame. Undo stays until the person leaves the screen; no timer and no confirm dialog. This replaces Android's 4-second snackbar. If the removal fails on the server, the row comes back in place, the badge returns to its original row, and an InlineErrorRow sits under that row. Tapping the header ScopeChip expands one explanation in place: "Saved places are only for you. To share one with the people you live with, claim it." plus a text button "Claim this address" for the place Today uses. Every LandingBannerSlot line on this screen has a trailing 44pt action: the sync line uses "Review"; the account-switch and claim-notice arrival lines use "Close". One banner at a time. A successful Use for Today gives one light haptic tick; nothing else has a haptic. With Reduce Motion on, every change is a cross-fade. No swipe-only actions: every row action is also a menu item.

FOUNDATIONS COMPONENTS USED: ScopeChip (saved-place variant, expandable, under the title or in the Saved places group header; "Your household" variant on the home row) · StatusChip (new "Used for Today" variant, sun-outline glyph, saved rows only) · InlineUndo (removed-row variant, consequence in the same line) · WarmingSkeleton (row skeleton with the badge slot reserved) · OfflineNotice with FreshnessLine (offline variant) · InlineErrorRow (load failed; Use for Today failed; remove failed) · LandingBannerSlot (sync merge V6 with Review; new account-switched and claim-notice arrival variants with Close; one at a time).

ACCESSIBILITY: Reading order: title, scope chip (or group label and chip), the Today row, the precedence sentence, other rows, + Add a place. Each row is one element, for example: "1107 NE Birchfield Ct, Camas, Washington 98607. Saved Saturday 10 October. Used for Today." Its custom actions are Open, Claim this address and Remove; the visible menu button reads "More for 1107 NE Birchfield Ct". Arriving from the Today chip moves accessibility focus to the row Today uses; arriving from Today's claim notice moves focus to the arrival line. The badge is a word, never only a colour; the sun-outline and home glyphs are decorative, and the home row's caption carries its meaning. A disabled Use for Today stays focusable and gives its reason. Removed rows, the remove-failed row, the switching line, the sync line and arrival lines are role=status. Targets are 44pt / 48dp / 44px. At AX5 the label, city and saved date stack, the badge moves under the label, and labels wrap and never ellipsise.

INSTEAD OF:
- Instead of a chip or status on every row, draw one StatusChip on one saved row — because one mark reads instantly.
- Instead of a check glyph or a toggled-looking selected chip for "Used for Today", draw the neutral StatusChip with a sun-outline glyph — because it is a status, not a control, and the check belongs to Paid and selected choices.
- Instead of a radio group or settings picker, draw a list with a row menu — because this is a list of places, not a preference.
- Instead of a greyed-out saved row for a claimed home, draw a home row in its own "Your home" group with Open as its only action — because it is a fact, and leaving a home belongs in home settings.
- Instead of one "Only you" chip over a list that holds a home, split the groups and chip each — because scope must be true for every row.
- Instead of a separate "Where Today gets this" sheet, put the reason beside the badged row or on the home row, or above the list when Today uses something else — because this list already answers that.
- Instead of a "Remove this place?" dialog or a timed snackbar, collapse the row to Removed · Undo — because lasting undo is safer.
- Instead of "home" or "household" on saved rows, use "Saved place" — because a saved place is shared with nobody.

DONE WHEN: A web person who saved a place reaches this list from the Place tab and from the Today chip. Anyone can say which place Today uses and why within five seconds, including when it is not a row and when they have a home. No caption on screen contradicts another. Removing the Today place moves the badge in the same frame, a removed place never lingers on Today, and a failed removal visibly puts it back. A claimed address appears once, as a home, with no Remove. Every frame reads correctly in greyscale and at AX5.
