# Last review findings for f9-block-founders-panel (round 2). The fix after this round was applied but not re-verified.

- [major] (substance) The postcard preview shows invented copy that is not what the service prints. The panel's stated purpose is to let people 'see what goes out in their name before sending', so a preview that differs from the real card is itself misleading. The real card also carries the recipient opt-out line and a verified-homes count, and the preview omits both. Notes do not list the preview copy as invented or as a required template change.
  - evidence: backend/services/blockFoundersService.js inviteFrontHtml: 'Your block is forming' / 'Verified neighbors on your street are already comparing bills, flood costs, and more.' inviteBackHtml: 'A verified neighbor on <street> invited this address to Pantopus. ${countLine}' then 'pantopus.com/start' then 'This invitation was mailed through Pantopus; the sender chose the address but never wrote this text ... To never receive another: pantopus.com/no-mail/<code>'. The prompt's preview is 'Front: "A neighbor on NE Larkspur Loop invited you" / "See what's on public record for your address." Back: "From a neighbor on NE Larkspur Loop" · "pantopus.com/join · code 4K2P 7M"'. The Notes list names only 'the code'.
  - fix: Either draw the preview with the current template text: the front and back as printed, including 'A verified neighbor on NE Larkspur Loop', the count line '3 homes near you are already verified.', 'pantopus.com/start' and the opt-out line with an invented code. Or keep the new copy, add the opt-out line to the back, and add a Notes item: 'Preview copy is a proposed template change to inviteFrontHtml/inviteBackHtml; it ships only with that change, and the preview must render from the same template.'
- [major] (substance) The composer collapses the existing four address inputs into one field. This is not in the change list, and the server contract needs four separate parts.
  - evidence: BlockDetail.tsx InviteForm has `aria-label="Street address"`, `"City"`, `"State"` (placeholder 'ST') and `"ZIP code"`, and posts `{ line1, city, state, zip }`. blockFoundersService.cleanAddressInput requires line1, city, a 2-letter state and a ZIP. The prompt has 'Field label "Neighbor's mailing address", filled with "2430 NE Larkspur Loop, Vancouver, WA 98684"' and 'Keep every other existing element unchanged'.
  - fix: Keep the four existing inputs (Street address, City, ST, ZIP), filled with 2430 NE Larkspur Loop / Vancouver / WA / 98684, and put the counter above the group. Or add a numbered change '(8) the four address inputs become one field' with a Notes dependency that the client or server must parse it.
- [minor] (substance) The rank caption 'Permanent' is drawn as fact, but the SlotMeter copy rule forbids 'permanent' unless the data model guarantees it. The prompt handles this only as Notes item (e).
  - evidence: component-contract.md SlotMeter copyRules: 'Never 'permanent' unless the data model guarantees it.' The prompt has 'caption "Permanent". Spoken as "Block Founder number 3, permanent."'
  - fix: Keep it, but tie frame 01 to Notes (e) explicitly, or draw the fallback caption 'Yours while you live here' as an alternate on Notes.
- [minor] (substance) The ScopeChip 'Your household' is placed on a panel whose content is per-user (rank, allowance, link) and includes other households' names, so the chip misstates who the content belongs to.
  - evidence: The prompt has 'the ScopeChip "Your household"' in the header, while the rank, allowance and roster names ('#1 Marisol T.') are not household data.
  - fix: Add a Notes question on which scope string applies to the Block Founders header, or scope the chip only to the address line.
- [minor] (substance) The pending teaser string drifts from the LockedActionRow pending pattern ('expected Sep 19–26'). The research also asked for the mailed date and code expiry in the pending state.
  - evidence: The prompt has 'We're checking your postcard code — expected Thu 22 Oct to Thu 29 Oct'. The contract has 'We're checking your postcard code — expected Sep 19–26'. research-findings.md: 'The pending state shows: mailed date · expected window · code expiry date'.
  - fix: Use 'expected Thu 22 – Thu 29 Oct' to match the component pattern, and note on Notes that the mailed date and expiry live in the verify sheet.
- [major] (ux) The prompt contradicts itself. DONE WHEN bans every 'N of M' fraction except the SlotMeter's, but the hero allowance counter is itself an N of M ('4 of 6 …'), and the research requires it. Claude Design checking its work against DONE WHEN may strip or reword the counter.
  - evidence: prompt DONE WHEN: "No bar, ring or 'N of M' fraction appears anywhere except the SlotMeter's '2 of 5 open'." CONTENT: "Counter above the field: '4 of 6 postcard invites left this week'". per-surface-changes: "The postcard counter matches the server formula: '6 of 6 left this week · 3 base + 3 earned from referrals'".
  - fix: Change the DONE WHEN line to: "No bar, ring or 'N of M' fraction appears anywhere except the SlotMeter's '2 of 5 open' and the allowance counter 'N of 6 postcard invites left this week'." Add the same exception to TYPE item (6).
- [major] (ux) The layout makes the FIRST FIVE SECONDS promise impossible on phones, and progressive disclosure is missing. The counter is named as the third thing the eye hits, and 'Send postcard invite' is the primary action. But the reading order puts the composer after three unlock meters, the roster and 'See Fircrest on the map', and the whole panel sits below the Invite rewards card. On a 393x852 phone the counter is several screens down.
  - evidence: prompt FIRST FIVE SECONDS: "Third, the counter '4 of 6 postcard invites left this week'. Primary action: 'Send postcard invite'." ACCESSIBILITY: "Reading order: header, rank, tier, unlock meters, roster, counter, field, preview, button." ux-research-brief governing idea: "put the detail one tap away".
  - fix: Add TYPE item (8): "Move the postcard composer directly under the tier block. Below it come the roster (first 3 rows, then 'Show all N'), then the unlock meters." Update the reading order to "header, rank, tier, counter, field, preview, button, roster, unlock meters". State: "On phones the counter is the first thing under the tier block."
