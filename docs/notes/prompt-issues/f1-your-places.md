# Last review findings for f1-your-places (round 2). The fix after this round was applied but not re-verified.

- [major] (substance) The caption "Today always uses your home" makes an absolute claim that the design doc's resolver order contradicts. The prompt's notes flag only the custom pin. A recently viewed location also ranks above a home, and the prompt has no state for a home user whose Today runs on a location that is not in the list, so the caption and the above-list line would contradict each other on screen.
  - evidence: Design doc §3: "`resolveLocation` ... reads `UserNotificationPreferences` (custom pin), `UserViewingLocation`, `HomeOccupancy`, then `HomeOwner`/`Home`, in that order". Prompt: "show the above-list line only when Today uses a location that is not a row" and "caption 'Today always uses your home'". The notes' open question covers only "'Use for Today' writes the custom pin, which the resolver ranks above a claimed home."
  - fix: Extend the notes' open question to cover the viewing location: "UserViewingLocation also ranks above HomeOccupancy (doc §3). For 'Today always uses your home' to be true, the resolver must put the home above both, or the caption must change." Also add one rule: for a home user, if Today uses a location that is not a row, drop the home caption and show the above-list line instead.
- [minor] (substance) The inventory's reason for requiring instant removal was dropped. The prompt now says only that Today stops using the address "the next time it is viewed", which reads as permission for a stale Today.
  - evidence: Inventory uxNote: "removal must invalidate queryKeys.hubToday ... the address keeps rendering for two minutes after removal, which on an 'only you' surface reads as a privacy failure." v1: "Removal must look instant everywhere". Prompt: "After Remove, Today stops using that address the next time it is viewed."
  - fix: Replace that sentence with: "After Remove, Today never shows that address again, even if it is already open: a removed address still showing on Today reads as a privacy failure on an 'Only you' surface."
- [minor] (substance) In Maya's grouped frames the prompt never says whether the home row also carries the "Used for Today" StatusChip. The rules "Exactly one row carries the StatusChip" and "no chips" conflict with the home row's ScopeChip, so two designers could draw this differently.
  - evidence: Prompt: "Exactly one row carries the StatusChip 'Used for Today' variant ... Every other row carries nothing: one badge slot, one menu button, no chips" and, for the home row, "home glyph ..., 'Your household' chip, caption 'Today always uses your home'". Contract StatusChip: "No two chips on one row."
  - fix: Add: "With a home, the home row carries no StatusChip; its caption 'Today always uses your home' is the Today marker and its reason, and no saved row is badged."
- [minor] (substance) The deep-link arrival from the Today chip scrolls and fades the highlight but does not move accessibility focus, which the research brief requires.
  - evidence: Brief §5: "Deep-link highlights also move accessibility focus." Prompt: "scroll the row Today uses into view once and fade its highlight."
  - fix: Append: "and move accessibility focus to that row."
- [minor] (substance) The inventory's precedence string "A home you've claimed always wins" was replaced without a note. The new string "Your claimed home comes first." is listed as invented, but the replacement is never recorded.
  - evidence: Inventory contents: "('Today uses the address you saved most recently' / 'A home you've claimed always wins')".
  - fix: On the Notes artboard, add: "'A home you've claimed always wins' (inventory) is replaced by the home-row caption and the disabled-reason 'Your claimed home comes first.'"
- [minor] (ux) The home row says "Today always uses your home", but the design doc ranks a recently viewed location above HomeOccupancy. For a home user who looked at another address, that caption would be false. The Notes open question covers only the custom pin, not viewing locations.
  - evidence: docs/first-person-loop-design-2026-09-16.md §3: "resolveLocation ... reads UserNotificationPreferences (custom pin), UserViewingLocation, HomeOccupancy, then HomeOwner/Home, in that order". Prompt: caption "Today always uses your home"; Notes: "'Use for Today' writes the custom pin, which the resolver ranks above a claimed home."

Extend the Notes open question: "A recent viewing location and the custom pin both outrank a home in resolveLocation; for the home caption to be true, the server must rank the home above both for home users." In EDGE CASES, add: "If Today uses a viewed or pinned location for Maya, the home row drops its caption and the above-list other-location line appears."
