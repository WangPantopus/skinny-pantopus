PART 1 — BOARD CONVENTIONS (these apply to every artboard on this board, all 61 of them)
==================================================================

1.1 Artboard names. Every artboard is named "00c · <ComponentName> · <NN-what> · <light|dark>", exactly as in the ARTBOARDS manifest at the end, and shows that name as a visible label above the frame, in caption 12/16 text.secondary. The last artboard is "00c · Notes".

1.2 The five artboards per component. Each of the twelve components gets exactly these five artboards, in this order:
  01-anatomy · light: one large specimen at 2x zoom with numbered callouts, then five labelled text panels: ACCESSIBILITY, COPY RULES, PLATFORMS, INSTEAD OF and USED IN.
  02-grid · light: the variant × state grid at 1x, one cell per listed combination.
  03-ax5-200-greyscale · light: two large-text columns side by side at the top: (a) iOS at AX5 Dynamic Type, where body is 53pt; (b) Android at 200% font scale with Android 14 nonlinear scaling. Underneath them, at full artboard width and at 1x, (c) a greyscale (0% saturation) copy of the full 02 grid.
  04-in-context · light: two or three mini crops of the named consuming surfaces, plus any platform variants the component section asks for.
  05-grid · dark: the same grid as 02, in the same layout, in dark tokens (per 1.6), plus the 1x anatomy specimen in dark, top left.

1.3 Canvas and widths. Artboards are at least 1440 wide, on surface.app. Grow an artboard's width or height to fit its cells at 1x; never scale a cell down. Unless a cell says otherwise, draw each row at iOS width: a 393pt frame with 16pt side margins, so the row content is 361pt wide. Where a component section asks for Android, draw the row in a 412dp frame (380dp content). Web 390 uses a 390px frame, and web 1440 uses a 720px list column.

1.4 Callouts. Callouts are drawn outside the component: a numbered circle (caption, text.secondary outline), a 1px text.secondary leader line, and a caption that gives the size in pt/dp/px and the token name, e.g. "② title · body 16/24/400 · text.primary". Callouts never overlap the component. Show spacing with 1px dimension lines and a number ("16pt · spacing.4"). Every 01-anatomy also carries a "web menu" callout that states how the component's custom actions appear on web (per 1.14).

1.5 Grid layout and labels.
  - Variants are rows, labelled at the left in label 13/18 text.strong. States are columns, labelled at the top in overline 11/16/600.
  - Label every variant row exactly "<code> · <slug>" (e.g. "V1a · pickup-both") and every state column exactly "<code> · <slug>" (e.g. "S2 · highlighted-arrival"), using the codes and slugs given in each component section.
  - Give every cell a caption under it, in caption 12/16 text.secondary, exactly "<Component> · <variant slug> · <state slug>" (e.g. "DateRow · deadline-voter · done").
  - Each cell draws the component at 1x. Draw only the cells listed in the component's GRID CELLS. Any grid position that is not listed stays empty canvas: no frame, no label, no n/a text.
  - An "n/a" cell appears only where this prompt writes "n/a"; there, write "n/a — <reason>" in caption text.secondary inside a plain cell, with the normal cell caption under it. Never draw a ghost component in an n/a cell.

1.6 Tokens. Use token names only. Light: surface.base #FFFFFF, raised #F9FAFB, sunken #F3F4F6, app #F6F7F9; text.primary #111827, strong #374151, secondary #6B7280, muted #9CA3AF (placeholders only; nothing on this board uses it); border.default #E5E7EB, strong #D1D5DB, subtle #F3F4F6, focus #0284c7; primary.50 #f0f9ff, primary.700 #0369a1; success #059669; warning #D97706; error #DC2626 / errorBg #FEF2F2; info #0284c7 / infoBg #F0F9FF; identity.home #16A34A. Dark: surface.base #0F172A, raised #1E293B, sunken #0F172A, app #020617; text.primary #E5E7EB, strong #F1F5F9, secondary #94A3B8, muted #64748B; border.default #1F2937, strong #374151, subtle #1E293B, focus #38BDF8; dark links use dark border.focus (#38BDF8).
  The dark token set has no infoBg, errorBg, primary.50, primary.700 or semantic entries, and dark sunken equals dark base, so every sunken shape would vanish on a base row. On every 05-grid · dark artboard, use exactly these substitutes, and list each one on Notes:
  (D1) Highlight: a dark surface.raised wash plus the 4pt leading bar in dark border.focus (see 1.8). On a row that already sits on raised (D3), use the leading bar alone.
  (D2) Write-failure fill: dark surface.raised plus a 1.5px error border.
  (D3) Rows that sit on sunken in light sit on dark surface.raised in dark, with dark text.strong.
  (D4) Any surface.sunken fill (skeleton bars, avatar circles, StatusChip, ScopeChip and "Statewide — WA" chip fills, thumbnail slots, the disabled CTA) becomes dark surface.raised when it sits on a dark base row, and dark border.strong when it sits on a dark raised row. Text inside keeps dark text.strong.
  (D5) Selection fill (ThumbnailRail selected row, ChoiceChip selected): dark surface.raised plus a 1.5px dark border.focus edge plus a leading check in dark border.focus. Never primary.50 in dark.
  (D6) Anything drawn in primary.700 that is not a link (the upload ring, the retry and minting spinners, the unread dot) uses dark border.focus in dark. The upload ring track is dark border.strong.
  (D7) Semantic glyph hues (success tick, warning glyph, error glyph) and the identity.home rule keep their light values in dark, on glyphs and rules only, never on text. Check each at 3:1 or better against the dark surface it sits on, and write the ratio in a caption beside the first occurrence.
  (D8) Card edges: any card in dark (the LockedActionRow V3 card, the InlineErrorRow V5 host card, any card in a dark cell) gets a 1px dark text.secondary keyline, because dark border.default on raised is 1.00:1. Write its ratio in a caption beside the first occurrence.
  Increase Contrast: no separate artboard. Every 4.5:1 text and 3:1 graphic check on this board must also hold under Increase Contrast. Under Increase Contrast, cards in light get the same 1px text.secondary keyline as D8; nothing else changes. Write this once as a caption on each 05 artboard and list it on Notes.
  Row separators are 1px border.default hairlines, inset 16pt from the leading edge. They are decoration only: no row depends on a hairline as its only edge.

1.7 Type. Use only the scale: body 16/24/400 · bodyMedium 16/24/500 · bodySmall 14/20/400 · bodySmallMedium 14/20/500 · label 13/18/600 · caption 12/16/400 · captionMedium 12/16/500 · overline 11/16/600 caps +0.5. Use SF Pro on iOS, Roboto on Android and system-ui on web. Amounts use tabular figures.

1.8 Targets, focus, highlight, selection and disabled actions (every component).
  - Targets are 44pt on iOS, 48dp on Android with 8dp gaps between targets, and 44px on web. In each 01-anatomy, draw every target as a dashed 1px text.secondary rectangle labelled "target 44pt / 48dp / 44px".
  - A ProvenanceMark, a glyph or a dot is never a target by itself. The enclosing row or button is.
  - Focus is a 2px border.focus ring drawn 2px outside the whole row. When a row holds a separate target (link, overflow, Retry, Resend, Add, dismiss), focus on that target rings that target only.
  - Highlight (arrival from a notification) is an infoBg wash across the full row plus a 4pt border.focus bar on the leading edge, full row height. It has no outline and never carries a check glyph. If the row carries a 2px identity.home rule, the bar sits directly inside that rule. In the "on arrival" frame, the focus ring is also present, drawn 2px outside the row, so bar (inside) and ring (outside) never touch.
  - Selection, where it exists, is a primary.50 fill plus a leading check glyph (dark: D5).
  - Focus, highlight and selection must each look different. Draw one focused cell beside each highlighted or selected cell the component section asks for.
  - Disabled text actions look the same on every component: the label in text.secondary (never primary.700, never text.muted), kept focusable, with a reason caption directly under it in caption 12/16 text.secondary. Disabled filled controls (the LockedActionRow V1 CTA) use a surface.sunken fill with a text.strong label (dark: D4).

1.9 AX5 / 200% rules (every 03 artboard).
  - Text wraps and never truncates or ellipsises, except where a component names the one field that truncates first.
  - Side-by-side pairs stack vertically.
  - Trailing elements (amount, mark, chevron, text action) move below the text block, aligned to the text's leading edge.
  - Leading glyphs and marks scale with the text, and ProvenanceMark keeps its shape.
  - Row height grows, and the minimum heights below are minimums only.
  - Label each column "iOS · AX5 (body 53pt)" and "Android · 200%".

1.10 Greyscale (every 03 artboard). Draw the full 02 grid desaturated, with the same labels and cell captions. Beside it, write one caption per state or variant naming the non-colour cue that carries it, for example "done = tick glyph + 'You marked this done'" or "highlighted = 4pt leading bar". If a cell only reads through colour, that is a defect: fix the component, not the caption.

1.11 Motion. Highlights fade out over 300ms or less. Under Reduce Motion they cross-fade. Under Reduce Motion, spinners are removed and the in-progress label ("Sending…", "Reissuing…", "Retrying…", "Making a link…") stays as static text. Idle loops stop within 5s.

1.12 Components from other Foundations boards. These rows embed components designed on other boards: ProvenanceMark, SourceCaption, ScopeChip, KindGlyph, StatusChip, ChoiceChip, FreshnessLine, OfflineNotice, InlineUndo and WarmingSkeleton. If the published Pantopus design system already contains one of them, use it. Otherwise draw this stand-in exactly and label it "stand-in":
  - ProvenanceMark: OFFICIAL = solid disc; ON RECORD, NOT CONFIRMED = ring with a stroke of at least 1.5px; YOU ADDED = solid disc with the tick knocked out as a cut-out, never a second colour. Ink is text.secondary, or dark text.secondary in dark mode. Size S = 16pt in rows; XS = 12pt minimum. The spoken names are "official", "on record, not confirmed" and "you added this". Filled vs hollow means provenance and nothing else. Each surface prints the word once, as the legend line "● Official · ○ On record, not confirmed · ✓ You added this" in caption text.secondary, or as the word beside the first mark.
  - SourceCaption: caption 12/16 text.secondary, "Authority · scope · as-of". It wraps and never ellipsises the authority. On sunken it is text.strong.
  - ScopeChip: pill, height 24pt, surface.sunken fill, a 12pt glyph plus label 13/18 in text.strong. When the chip opens the scope control, its hit area is 44pt / 48dp; draw that target. The chip strings are "Saved place · Only you" (person glyph) and "Your household" (house glyph). They are spoken as "Visible to only you" and "Visible to your household". The approved sentence forms are "Only you will see this." and "Everyone in this household will see this." Where finance permissions differ between members, the sentence names the people instead ("You and Sam can see these"); never "Everyone" there.
  - KindGlyph: 24pt line icon, 2pt stroke, text.strong, one distinct drawing per kind: garbage, recycling, garbage+recycling, notice deadline, warranty ends, HOA dues, property-tax (appeal / due), voter registration, bill. Never one generic calendar icon.
  - StatusChip: pill, height 24pt, captionMedium, surface.sunken fill, text.strong. Any semantic hue goes only on a leading glyph. Exactly one per row.
  - ChoiceChip: pill, radius pill, 32pt visual height inside a 44pt / 48dp target, label 13/18. Selected = primary.50 fill + primary.700 text + a leading check glyph (dark: D5). Unselected = a 1px text.secondary edge + text.strong label (see Notes 3). The focus ring is distinct from selection. At AX sizes the chips wrap to radio rows.
  - InlineUndo: the row collapses in place to "<what happened> · Undo". It is announced with role=status, and Undo is focusable. The Undo target is 44pt and stays until the user leaves the screen. There is no countdown.
  - WarmingSkeleton: surface.sunken bars (dark: D4) in the final geometry and at the final height. There is no text inside. The container is announced once as "Loading" (aria-busy on web), not shape by shape. It shimmers, or is static under Reduce Motion.
  - FreshnessLine / OfflineNotice: caption text.secondary, e.g. "You're offline · as of 5:52 PM" (invented). Each disabled control gets a reason caption under it (1.8). There is no banner colour.

1.13 Fixtures. Use the house-style FIXTURES. TODAY is Mon 19 Oct 2026, 6:10 PM Pacific. Relative counts in this prompt are computed from that date. Any string this prompt marks "(invented)", and any string you add yourself, goes on the Notes artboard. Dates always show the weekday ("Fri 23 Oct"). They never use numeric formats like 10/23/2026, and never "midnight".

1.14 Platforms default. Unless a component's PLATFORMS line says otherwise, the contract has no platform differences for it: write "No platform differences" in its PLATFORMS panel. On every component:
  - Custom actions are VoiceOver custom actions on iOS and TalkBack custom actions on Android.
  - On web, custom actions that are not already visible buttons get a visible row menu button: a 20px ellipsis in a 44px target at the row's trailing edge. Where a row already has an overflow button or visible buttons for those actions, that is the web menu; do not add a second one. Every web crop in 04 draws this button where it applies.
  - Disabled controls stay in the iOS and Android accessibility tree with their reason as a hint.

1.15 In-context crops (every 04 artboard). Every crop that shows a ProvenanceMark also shows the legend line from 1.12 (or the word beside the first mark) and the ScopeChip for that surface ("Your household" for Home A, "Saved place · Only you" for Place B). Label each crop "<surface id> · <platform>".

ACCESSIBILITY (panel):
  - The whole row is one element and the target (min 56pt), read in visual order. The mark and glyph are not targets.
  - Pattern: "<title>, <line 2 as shown>, <authority, scope>, <mark name>". The spoken label says only the dates the row shows; "Tomorrow" is spoken as "tomorrow" with no absolute date. Example: "Recycling and garbage, tomorrow, Waste Connections city schedule, on record, not confirmed."

  - Custom actions: Edit · Remind me · Where this comes from · Mark done. On web they sit in the ⑩ row menu button.
  - Non-colour encoding: the glyph shape carries the kind, the mark shape carries provenance, the leading bar carries highlight, and the words carry done.
  - Contrast: text at least 4.5:1, mark at least 3:1.

COPY RULES (panel):
  - For deadlines, the title names the action: "Tell your landlord in writing by Mon 1 Mar 2027".
  - Received-by deadlines say "must arrive by".
  - Dates are spelled out, never 10/11/2026.
  - Beyond tomorrow, the relative count comes first: "in 7 days · Mon 26 Oct". Conditional rules (V4) are exempt from the relative count.
  - Source captions carry a scope word: "Clark County Treasurer · county-wide".
  - Pickup titles use exactly "Recycling and garbage" or "Garbage only".
  - Holiday moves read "moved to Fri 27 Nov", never "delayed" or "cancelled".
  - "I did this" reads "You marked this done" and stays Only you.

PLATFORMS: default (1.14). Web adds the ⑩ row menu button.

INSTEAD OF (panel):
  - Instead of red text or an overdue chip on an annual date that has passed, draw the next occurrence with its "Every year" caption. Annual dates never inherit overdue red.
  - Instead of one generic calendar icon for every row, draw the specific KindGlyph. The glyph is what tells kinds apart without colour.
  - Instead of a greyed placeholder row for a date the viewer may not see, draw nothing. A ghost row leaks that something exists.
  - Instead of a numeric date like 10/26/2026, draw "Mon 26 Oct". The weekday is what people plan by.
