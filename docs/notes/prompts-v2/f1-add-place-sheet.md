WHERE IT LIVES & HOW PEOPLE ARRIVE: The sheet opens over Today and over the Place tab. Entry points: (1) Today's no-place card, whose button is now "Add a place" (it was "Preview an address"); (2) "+ Add a place" on Your places, in the empty state and at the list foot; (3) a widget tap when there is no place (the widget reads "Save an address to see today here"), which opens Today with this sheet on top; (4) the widget how-to's "Save an address first" button, which lands in the same place as (3); (5) the place file's Address row when it is empty; (6) proposed: "Save this address" on the signed-in compare arrival header. "Preview an address" stays only on buttons that really go to the /start preview. The sheet receives nothing, except from the compare arrival header, where it opens in the selected state (03) with the address the person just typed already confirmed.
Where it leads: on success the sheet returns to where it opened. From Today, the widget, the place file's empty Address row or the compare header, it dismisses onto Today: Today's location row reads "1107 NE Birchfield Ct · Saved place · Only you" (when Today switched), Today opens in its warming state, and a one-line role=status row sits directly under the location row until the person leaves Today (not a toast). From Your places, it dismisses onto Your places: the new row appears at the top (with the "Used for Today" StatusChip if Today switched), and a role=status line under the title reads "Saved privately. Today now uses 1107 NE Birchfield Ct." with a text button "See Today". For a home user, a chosen-place user or a viewed/pinned-location user, that line uses the matching "Today still uses…" string below, and they stay on Your places.

WHO AND WHEN: Jordan Lee, 36, moved from Portland to PLACE B on Fri 9 Oct. On Sat 10 Oct at 6:10 PM, the day after the move, he opens Your places on his iPhone, taps "+ Add a place" and types his new address from memory, misspelled: "1107 NE Birchfeild". He already has older saved places, including Mom's house. These frames are dated Sat 10 Oct, the fixture save day, not TODAY. Frame 5 shows the unnamed signed-in first-place case over Today's no-place card; the sheet shows no name.

THE ONE JOB: Type one address, save it privately, and see truthfully which place Today now runs on.

FIRST FIVE SECONDS: The eye lands first on the focused "Street address" field (caret in it, keyboard up on iOS and Android), then on the suggestion list beneath, then on the Save button with "Only you will see this." under it. Save is the single primary action.

(not shown on the first-place frame).
Not found: "We couldn't find that address." plus the text button "Can't find it? Enter it line by line". It opens five fields in the same sheet: "Street address" (keeps the typed text), "Apt, suite or unit" (optional), "City", "State" (a picker, default "WA") and "ZIP code".
Lookup service down: the manual fields open with "Address search isn't working right now. Enter it line by line instead."

Saved status (Today's status row, or the line on Your places): "Saved privately. Today now uses 1107 NE Birchfield Ct."
Chosen-place variant (if Jordan had picked Mom's house with Use for Today): "Saved privately. Today still uses Mom's house, the place you chose."
Viewed-location variant (Today runs on a location he looked at recently that is not a saved row): "Saved privately. Today still uses the location you looked at recently." Pinned twin: "Saved privately. Today still uses the location you pinned."
Claimed-home variant (Maya, HOME A): "Saved privately. Today still uses your home."

LAYOUT & VISUALIZATION: A deliberately compact sheet: one field, a plain list, one button and one scope sentence. No map, pin, thumbnail, reading, grade, "what you'll get" list, progress dots or second page, because the reading appears on Today a second later. Suggestion rows are text only (48pt / 48dp / 44px), with the untyped part at medium weight in the same size as the row text. The not-found message, manual fields, outside-area line and duplicate chip replace the suggestion list in place; the sheet never opens a second page, and it keeps its height when a state replaces the list so nothing resizes under the thumb. In the duplicate state, the AddressChip duplicate variant shows its message only; its inline "Use for Today" action is hidden because the primary button carries it. At AX5 the sheet scrolls. On Today after saving, the status row is one line directly under the location row (bodySmall, text.primary). On Your places after saving, the status line sits under the title and above the list.

INTERACTION, MOTION & HAPTICS: Suggestions update as the person types. No indicator for lookups under 1s; after that, "Looking up addresses…" in the list slot. Tapping a suggestion selects it and enables Save. Save shows its loading state and locks the field. On success the sheet dismisses with the platform transition onto the screen it opened from, and iOS and Android give one light haptic tick. "See Today" on the Your places status line opens Today. Close, Android Back and web Escape discard the sheet and return focus to the button that opened it. After a successful save, focus goes to the status row or line. With Reduce Motion on, list changes and dismissal are cross-fades.

FOUNDATIONS COMPONENTS USED: AddressChip (selected state; duplicate variant with a dated message and its inline action hidden) · ScopeChip (sentence form "Only you will see this."; the saved-place chip on Today) · StatusChip ("Used for Today" on the new row on Your places, as drawn in that project) · OfflineNotice (form-offline variant) · InlineErrorRow (save-failed variant, value kept).

ACCESSIBILITY: Title "Add a place" is unique, and focus is trapped in the sheet. The field uses street-address autofill; ZIP code uses a number keyboard; State is a labelled picker. "5 addresses found" and each error are announced politely and tied to the field. Each suggestion row is one element that reads the full address. Save's disabled state explains itself: "Pick an address first". Focus stays visible above the keyboard. The status row on Today and the status line on Your places are role=status. At AX5, the manual fields are one column and addresses wrap. Nothing depends on colour.

INSTEAD OF:
- Instead of a map, pin, preview card or reading, draw one field and a plain list — because this sheet only saves, and Today shows the reading.
- Instead of "Preview an address" on buttons that open this sheet, write "Add a place" — because a label must predict where it goes.
- Instead of a link to /start, keep the person signed in, in this sheet — because /start is the signed-out funnel.
- Instead of always jumping to Today after saving, return to the screen the sheet opened from — because someone adding from Your places expects to see the new row.
- Instead of refusing an address outside Clark County, save it and name the layers that work there — because the preview works nationwide, and a false "not served" is the top complaint about address apps.
- Instead of a dead-end "couldn't find" message, offer line-by-line fields, with a unit line, in the same sheet — because people fall back to typing when autocomplete fails.
- Instead of asking someone to retype a saved address or one they just typed on the compare header, show it selected or as an "Already saved" row — because we already hold it.
- Instead of silently switching Today, or claiming it switched when a chosen place, a home, or a viewed or pinned location stays in charge, name what Today uses — because nobody should be surprised by what Today shows.
- Instead of calling the address being saved a "home", or using "claim" or "household" for it, say "place" and "Only you" — because claiming is a much heavier promise (the only exception is the claimed-home user's line "Today still uses your home.").

DONE WHEN: A signed-in person on any platform can go from "Add a place" to the saved address in one sheet, with no dead end, and ends up back where they started with a true sentence about which place Today uses. A typo still finds the address. A failed lookup still saves. A Portland address saves with its layer line. A duplicate needs no retyping. Nobody is surprised by which place Today uses afterwards, including people with a home, a chosen place, or a viewed or pinned location.
