- F6: ticks are SharedPreferences, per-home, per-device (JustMovedCard.kt:121-135, prefs "just_moved"), so nothing survives a reinstall or crosses to web/iOS. Only five steps exist (L81-118) with no `register`/voter step, and the card is gated on a move-in date via isRecentMove (L61-69) and hosted only on the Place dashboard (PlaceDashboardScreen.kt:197-212) — not on Today, and not at all when homeId is blank (L200).
- F11 has no Android substrate. The `TodayDetailUiState.kicker` slot the design names (TodayDetailUiState.kt:74) belongs to the hub *briefing* screen (hub/today/…), which is a different surface from the Today *tab* (place/today/… -> PlaceTodayDetailContent.kt:58-111, which has no kicker at all). kicker is a plain String from TodayDetailMapper; there is no keeper name/species/mood model, no home-settings client writing HomePreference.settings, and no naming sheet anywhere.
- §5's instrumentation has no Android emitter. There is no funnel-events API client in the Android tree — no /api/public/funnel or /api/funnel call anywhere under frontend/apps/android/app/src/main — so `session_open` (and every t0_* event F8 relies on) would need a new endpoint client, a new deep-link `?src=` parser branch (DeepLinkRouter.kt has no src handling), and a widget-snapshot-written reporter that does not exist. Activation as defined in §5 is therefore unmeasurable on Android as shipped.
- Test coverage the design assumes is partly absent. F1 cites "Android TodayTabViewModel tests" — no such file exists; the only Today tests are for the hub briefing (TodayDetailViewModelTest.kt, TodayDetailMapperTest.kt, TodayDetailSnapshotTest.kt).
