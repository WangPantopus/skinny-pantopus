# Research contradictions that target the house style itself

- (accessibility-inclusive: WCAG 2.2 AA (in) v1: The token list has no accessibility constraints. text.muted #9CA3AF is offered as a text colour, primary.DEFAULT #0284c7 is the brand action colour (web buttons are bg-primary-600 with white text), and semantic hues are listed as text colours. No prompt's STATES list includes a large-text, greyscale or screen-reader frame, and neither the house style nor the design doc mentions Dynamic Type, touch targets, contrast or VoiceOver.
  research: WCAG 1.4.3 and 1.4.11, Apple HIG and Android all require 4.5:1 for text and 3:1 for meaningful graphics. Computed: text.muted 2.54, primary.DEFAULT and white-on-primary 4.10, warning 3.19 (3.07 on warningBg), success 3.77, info on infoBg 3.84, error on errorBg 4.41, text.secondary on sunken 4.39, border tokens 1.24 to 1.47. Apple's Larger Text criteria ask for testing up to the largest sizes (AX5 body 53pt), and Android 14 asks for testing at 200%.
  do: Add an ACCESSIBILITY block to the house style. (1) Text is at least 4.5:1 and meaningful graphics at least 3:1, in light, dark and Increase Contrast. text.muted is never used for readable text. Filled buttons and inline links use primary.700 (dark mode links use #38BDF8). Semantic tints carry text in text.primary with the hue only on the glyph. (2) Targets are 44pt iOS, 48dp Android with 8dp gaps, and 44 CSS px on web; a mark is never a target by itself. (3) Every prompt adds an AX5/200% frame and a greyscale frame. Pairs stack, meaningful text wraps, and sheets may scroll. (4) Nothing relies on colour alone, and filled/hollow means provenance only. (5) Every chart has a summary sentence, spoken labels and a list or table. (6) No gesture-only or hover-only action, and every sheet has a visible Close. (7) No timed-only undo and no seconds countdowns. (8) Reduce Motion turns movement into fades. (9) Plain language at grades 6–8, sentence case, verb-led buttons, acronyms expanded. (10) Focus is visible and never under sticky UI, and selection looks different from focus.
- (claude-design-prompting: how to prompt C) v1: 'Before designing, open these two projects [claude.ai/design/p/... share links] and use them as the source of truth for every token, component and layout convention.'
  research: Claude Design documents design systems as org-level objects built from codebases, design files and uploads. When published, every project created from the homescreen uses them automatically. Opening another project by share link is not in the Get-started article (asked directly: NOT PRESENT). Anthropic's Ryan Mather: set up the design system and core screens first.
  do: Publish a 'Pantopus' design system built from the token files, the two projects' exported HTML and core-screen screenshots. Create each surface project from the homescreen. Change the preamble line to 'This project uses the published Pantopus design system; screenshots of the host are attached.' Keep the links for humans only.
- (claude-design-prompting: how to prompt C) v1: 'DESIGN DIRECTION: clean, trustworthy, warm.' The type scale is given but no font family, corner radius, elevation or spacing unit is named.
  research: Anthropic (Opus 4.8 guide): the model's persistent default is warm cream (#F4F1EA), serif display type, italic accents and terracotta. Generic style instructions shift it to another fixed palette. 'Specify a concrete alternative. The model follows explicit specs precisely.'
  do: Replace 'warm' with concrete rules: the named sans family from the codebase, the radius and elevation values, the spacing unit, 'no serif, no italic accents, no cream or tinted-paper backgrounds; warmth comes from copy voice and primary.50 selected states'.
- (claude-design-prompting: how to prompt C) v1: A blanket 'DRAW BOTH LIGHT AND DARK', while 46 of 59 prompts' state lists and every 'frames: N' count leave out dark twins, and f8-og-compare-card specifies light only.
  research: Anthropic: current models follow instructions literally, do not carry an instruction from one item to the next, and need the scope stated explicitly. Figma: audit guidance for conflicting information.
  do: Remove the blanket line. Each prompt ends with an explicit ARTBOARDS manifest that names which frames get dark twins (default: the dense frame plus one state-coloured frame; full dark sets only for widgets, the provenance specimen and the scale strips).
- (claude-design-prompting: how to prompt C) v1: Each prompt closes with a 'DO NOT' list (about 464 'do not' / 'never' phrasings across the pack), several without a stated alternative.
  research: Anthropic: tell Claude what to do instead of what not to do, and give the reason. Positive instructions and examples beat negative ones. Emphatic prohibitions can over-trigger.
  do: Keep a short INVARIANTS block in the preamble. In each prompt, rewrite the DO NOT lines as 'Instead of X, draw Y because Z', keeping the existing WHY sections, which already match the guidance.
