## Local verification

The dedicated Android emulator uses the real local Express backend and
Supabase Auth/Postgres. Two newly created synthetic accounts isolate a
saved-place-only person from a verified homeowner. The notification lists
contain 80 synthetic rows per account. A local forwarding proxy can delay or
refuse selected requests while forwarding normal traffic to the real backend.
Credentials, tokens, runtime logs and raw database data remain outside Git.

The API setup checks pass for both sign-ins, My Homes, notifications,
saved places and feed preferences. Both Today paths return live weather and
alert sections. Air-quality retrieval is unavailable in this local environment.
These API checks establish the fixture; they do not substitute for using the app.

The combined debug APK built successfully and ran on Android 15 / API 35.
The local forwarding proxy preserves the request host so native device-proof
validation uses the same origin as the app. Socket.IO polling reaches the
backend; this setup does not establish a native WebSocket transport result.

### Repair found in 2174

Start Mark all read with a delayed refusal, switch to Unread while the write
is pending, then refuse the list read with HTTP 403. The private rows correctly
stay hidden after the delayed write returns, but the header remains Pending
even though the action finished. `finishReadAction()` skipped all presentation
updates when the list was in an error state.

The repair updates only the disabled header action in that state, preserving
the permission error and keeping rows hidden. The refusal path also disables
the header immediately. The verification-branch repair is `41feffc5f`; the
isolated commit for PR 2174 is `cdf487480`. The rebuilt APK passed the same
native sequence: after the 403 and delayed 503, the header read Mark all read
with `enabled=false`, the permission error remained, and no old rows returned.
Clearing the injected refusal and tapping Try again restored the list.
The post-repair quality run passed. Commit `cdf487480` was pushed directly to
2174's existing `codex/isa-notification-actions` branch. Its new-head CI
completed successfully. The follow-up below also changes 2177. No PR was merged.
