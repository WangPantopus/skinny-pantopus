# Home task collection capabilities — September 10, 2026

The task list now returns an explicit `collection_capabilities.can_create` alongside its existing authenticated `task_session`. This lets native clients show Add only when the current record authorization permits creation, including an empty collection and the existing exact private-creator first-use flow. It does not infer authority from a role, a populated list or generic Home membership.

The additive 150000 migration derives the boolean from the final locked `home_record_context` in the existing record projection. Current `tasks.edit` or `tasks.manage` permits creation only after the projection's existing access and `tasks.view` checks succeed. All source locks, private first-use checks, media filtering, per-record capabilities, current access recheck and service-only RPC privileges remain intact. No role defaults change. A missing or malformed capability is a retryable 503 API-contract failure, rather than an inferred grant. Task list/detail responses are private and non-cacheable and reject a supplied stale session scope before their database read. Legacy callers may still omit that optional read precondition.
