## Behavior and implementation

The service-only additive migration `20260913030000_home_current_residency_claims.sql` projects current pending requests only after fresh authority checks. It locks the Home and projected profiles before checking the current clock. Responses have private no-store headers, explicit session binding, safe public usernames and `name: null`. Legacy null dates and roles remain null; there is no backfill or invented relationship. Ordering is date descending, nulls last, then UUID descending. Duplicate claim or applicant IDs fail closed.

Both browser consumers—the Members & Security dashboard panel and owners/review-claim page—share validated queue content. Residency loads independently of ownership/comparison reads. The dedicated iOS and Android queue consumers use the same strict projection; the old raw loader was removed from each ownership view model. Each current view owns its loading generation and session. Backgrounding, account changes, failed reads, tab/navigation changes and protected-review presentation retire the previous rows. Selecting a row rechecks the exact current claim before opening the established decision workflow.
